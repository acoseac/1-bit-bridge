# The box as an audio output (`internal/alsa`, `internal/mpd`, `bridge output`)

The bridge as an output: on a Linux box with a DAC and MPD, it reports the DAC and a live reading of what the DAC receives, so the app's Signal Path can show it. Step one (2026-10-19) reads `/proc` and adds `bridge output dac`. Step two (the same day) finds the player and reads how MPD is set: `internal/mpd` is a read-only client, `internal/mpd/conf` reads `mpd.conf`, and `bridge output player` prints both. Step 2b adds `output.mpd` (`auto`, `on` or `off`) and `GET /v1/outputs` when that resolves on and the host is Linux. The record is in `ops/engineering-log.md` under that date.

- **`owner_pid` in a substream's `status` is a THREAD id**: the thread that opened the PCM, which for MPD is its output thread (`output:alsa`, not `mpd`). **Name and Tgid come from one read of `/proc/<tid>/status`.** When Tgid is that tid, the process name is the same Name; otherwise it is the Name line of `/proc/<tgid>/status`. **`comm` is only the fallback when that status has no Name line. Never read `/proc/<owner_pid>/comm` as the process's name**, and report both names.
- **An owner nobody can name is unknown, never an error**: a missing or unreadable `/proc` entry (hidepid, a thread that exited) or an `owner_pid` of 0 (outside this pid namespace) leaves that name null, and the reading is whole. **Don't turn it into a problem or a failed read.**
- **The reader takes its roots and carries no build tag**, so its tests read the captured trees in `internal/alsa/testdata` on all three CI OSes. Only `bridge output dac` refuses, and only the host's own tree, off Linux; `--proc-root` reads a tree anywhere. **Don't move the reader behind `//go:build linux`.**
- **A parser ignores a key it does not know, and reports a key it knows whose value does not parse**, a second line of a key the kernel prints once (the first value stands), and a block the kernel always prints whole that arrives without one of its lines (a file cut short). It never guesses a value: what did not parse is null. Kernels add lines, so a strict parser fails on the next kernel; a guessing one shows the app a reading nothing proved.
- **One altset is one `Format:` line and, since Linux 5.1, one `Bits:` line** (`sound/usb/proc.c` `proc_dump_substream_formats`, v4.19 through v6.17). The Format line is every name in the altset's bitmask, space-separated, in `snd_pcm_format_name` order; `SPECIAL` is `SNDRV_PCM_FORMAT_SPECIAL`, kept in that list, and a DSD format is any `DSD_` name wherever it sits. A second Format line is a repeated key, not another format. **Bits has been printed for UAC1 and UAC2 alike only since 5.1** (c7a13264918b); a stream without it is unknown, never cut short. Format, Channels and Rates have been printed since v4.19 and a missing one of those is still cut short.
- **Every read stays inside the roots it was given.** `pcmNp` and `subM` count when `Stat` says they are directories, and a stream file only when its target is a regular file, so a symlink to either is the target. A path that resolves outside its root is refused and not opened, so `--raw` cannot print it; the kernel's `/proc/asound/<id>` link to `cardN` stays inside the root and still reads. **Don't follow a link out of the tree.**
- **`--watch` compares readings without what moves on every read while audio plays** (`steadyView`: the buffer pointers, delay, avail, the timestamps, the measured rate and the packet size). **Don't add a moving value to the comparison**: it would print once a second for as long as anything plays.
- **The `alsa` types' JSON is `bridge output dac --json`'s diagnostic shape**, every key always present and every list `[]`. A `/v1` route that serves a reading wraps it in a DTO under `internal/api`, as the wire-type discipline in `wire.md` requires; **don't encode an `alsa` type from a handler.**
- **The fixtures are captures, byte for byte**, pinned to LF in `.gitattributes`; `testdata/README.md` names each synthetic file. A new case comes from `bridge output dac --raw` on a real box. **Never edit a captured file**: add a synthetic case beside it.
- **DAC capabilities come from every playback altset, and a native DSD rate is the altset's frame rate times the format's width.** `DSD_U32_*` is ×32, `DSD_U16_*` is ×16, `DSD_U8` is ×8. A DSD format whose width is not one of those is listed and adds no rate. PCM rate and bit depth come only from a format matching `S` or `U` plus digits (`S24_3LE` is 24); a DSD altset's `Bits` line and its frame rates are not PCM. **Don't read the running `hw_params` as what the card can do, and don't invent a multiplier.** `TestCapabilitiesFromTheIFiCapture`, `TestCapabilitiesFromTheSynthetic768AndDSD512`, `TestCapabilitiesTable` and `TestNativeDSDRate` pin it. `pcm768-dsd512` is the synthetic stream: 768 kHz PCM and DSD512.
- **An ALSA device string resolves to a card only when it names one.** `hw`, `plughw`, `plug` and `front` may name an index or a card id (`hw:N`, `hw:N,D`, `hw:CARD=ID`, `hw:CARD=ID,DEV=D`, and the same with `plughw:`), and the id match is exact: two cards with that id do not resolve. Any other name is a PCM looked up in `etc/alsa/conf.d/*.conf` and then `etc/asound.conf`, inside the config root beside the proc root the reader was given. A name defined more than once, in one file or across them, including a `pcm.!name` for a name already defined, is unresolved. A `pcm` stanza that is not `pcm.NAME { … }` or `pcm.!NAME { … }`, including a brace-nested `pcm { … }` and a dotted assignment such as `pcm.out.card 2`, makes the file unusable. A second `type`, `card`, `device` or `slave` in one block is unresolved. `slave.pcm`, dotted or a `slave { pcm }` block, is followed through `empty` and `plug` only, at most 8 hops, until a `type hw` whose `card` is an id or an index. A slave whose name contains `:` is a device string (`hw:`, `plughw:`, and the same plugins as a direct device), never a PCM block of that name. A `ctl` block and a `defaults` assignment are skipped, and `;` and `,` are separators. Inside a `pcm.NAME { … }` block, `@args`, `@func`, `$VAR` and any nested block this parser does not model make that name opaque: the chain that reaches it is unresolved, and the rest of the file still counts. The same directives inside a skipped `ctl` or `defaults` block are skipped with it. At the top level, `@hooks`, `@args`, `@func` and an include (`<…>`) make the whole configuration unresolved, and so does a file that is present but cannot be read. One such file makes the whole configuration unresolved: definitions from the other files are not used. A missing file does not. A string accepts only `\"`, `\\` and `\'`; any other escape makes the file unusable. A `dmix`, `softvol`, `rate`, `route`, `multi`, plugin, hook, include, cycle, a longer chain, a file this parser does not understand, or a missing file stays unresolved, and the route then lists each USB card with `isMPDsOutput` null. A resolved card that is in `/proc/asound/cards` is listed alone with `isMPDsOutput` true. **Don't guess a card.** `TestResolveALSADevice`, `TestResolveOutputDeviceVolumioChain`, `TestResolveOutputDevice`, `TestDuplicatePCMIsUnresolved`, `TestDuplicateKeyIsOpaque`, `TestSlaveDeviceString`, `TestNonPCMStanzaIsSkipped`, `TestStringEscapeIsOnlyQuoteOrBackslash`, `TestUnparsedFileDropsTheRest`, `TestUnmodeledPCMStanzaIsUnusable`, `TestAtDirectiveInsideSkippedBlock`, `TestPluginPCMDoesNotSpoilTheFile`, `TestResolveOutputDeviceVolumioChain` and `TestVolumioPCMNamesTheDAC` pin it.
- **A dead MPD session is dropped and dialled once more in that build.** The cached client is reused only for the same endpoint and password, so a config change dials fresh. A non-context error from `status` or `find` closes it; a cancelled caller does not. **Don't keep serving `unknown` and `mismatch` off a connection MPD has already closed.** `TestDeadMPDSessionIsRedialed`, `TestDeadFindRedialsOnce` and `TestSessionFollowsTheEndpoint` pin it.
- **`GET /v1/outputs` answers only when `output.mpd` resolves on and the host is Linux.** `on` is on even when nothing greets; `auto` is on when a configuration was read or a daemon greeted; anything else, and every host that is not Linux, is `404` `local_outputs_not_supported` and no `localOutputs` flag. The DTOs live in `internal/api`. **Don't encode an `alsa` or `mpd` type from the handler.** `kind` is the open string `mpd`; a client ignores a kind it does not know. `mpd` is a pointer, present only for kind `mpd`, and omitted for kind `bridge`. `mpd.version` is empty when the daemon is down. Each unresolved candidate card is its own element, with the same `mpd` and `pathRules` and a different `id` and `dac`. `isMPDsOutput` is `true` or `null`, never `false`. `addresses` are the advertised LAN IPs on which MPD's port greets `OK MPD`; loopback and link-local (`fe80::/10`, `169.254/16`) are never listed, the probes run together, and each probe has one deadline covering the dial and the read. None means `reachableFromLAN` false. The id is the SHA-256 of the data-directory identity (`OutputIdentity`, the same directory `deriveDLNAUDN` hashes, without the friendly name), the MPD endpoint, the card's ALSA id and its USB id, never the TLS fingerprint, the library name or the card index, and it is stable across restarts and certificate renewals. The session opens on the first call and closes about 60s after the last call, on a clock the route takes as `Now` and `AfterFunc`. The idle close does not run while a build is in flight; that build re-arms the timer when it finishes. One build runs at a time, on a context detached from the caller with its own deadline (about 15s), and a success is reused for 500ms. A build that hits that deadline is not cached, and a caller that disconnects does not cancel the waiters. **Don't dial from `/v1/health`:** the flag's auto probe is a separate short cache, keyed on one read of `output.mpd`, endpoint, conf and password, and it runs on a context detached from the caller so a cancelled request does not store a miss. Concurrent callers for one key share that in-flight probe. A result whose own deadline fired is not stored. `TestLocalOutputsGate`, `TestOutputsJSONKeepsEveryKey`, `TestOutputKindIsOpen`, `TestOutputsLANAddresses`, `TestLANProbesRunTogetherAndSkipLinkLocal`, `TestGreetDeadlineCoversDialAndRead`, `TestOutputsCacheAndIdle`, `TestProbeCacheFollowsTheConfig`, `TestProbeCachesTheConfigurationItProbed`, `TestProbeMissesShareOneFlight`, `TestProbeDeadlineIsNotCached`, `TestCancelledProbeIsNotCached`, `TestIdleCloseSkipsABuildInFlight`, `TestOutputsOneBuildInFlight`, `TestCancelledCallerDoesNotSpoilTheBuild`, `TestBuildDeadlineIsNotCached`, `TestOutputsIDStableAcrossRestarts` and `TestOutputIDIgnoresTheCardIndex` and `TestIsMPDsOutputIsTrueOrNull` pin it.
- **`output.mpd` is `auto`, `on` or `off`, and only `on` is a bridge with no library.** `auto` (the empty value too) is on when a configuration was read or a daemon greeted, which Validate does not decide. A loopback bridge still requires a library root, so a default install does not become output-only. A public bridge (`Config.IsPublic()`) may have no roots: Validate warns and does not fail. `on` with no roots loads, `bridge doctor` does not fail it, and serve starts and serves no tracks. Endpoint, conf and password are the overrides `bridge output player` takes. **Don't log the password or put it in an error, and don't dial from Validate.** `TestOutputOnlyConfigHasNoRoots`, `TestOutputModeRejectsAnythingElse`, `TestAutoStillRequiresARoot`, `TestOutputOnlyBridgeStarts` and `TestDoctorPassesWithNoRoots` pin it.
- **The MPD client sends only the allowlist, and `exchange` is the only writer.** The commands are `status`, `stats`, `outputs`, `replay_gain_status`, `currentsong`, `config`, `commands`, `find`, and `password` solely as the argument `Dial` sends when the caller already holds one. `find` takes one path, and `commandLine` builds both quoting levels from it: the filter value inside `(file == "...")` escapes `\`, `"` and `'` (MPD 0.24.4 `src/song/Filter.cxx` `ExpectQuoted`, and the worked example in `doc/protocol.rst` "Escaping String Values"), then the whole expression is one protocol argument quoted the way a password is. A caller never supplies filter text. A path containing a newline, a carriage return or a NUL is refused with `mpd: path refused` and nothing is written. There is no method that starts, stops or seeks playback, and none that edits the queue or the database. **Don't add a command, or a write, that `exchange` does not check first, and don't let a caller pass the filter text**; a refusal is `mpd: command refused` and names neither the command nor the argument. `TestAllowlistIsExactlyTheReadCommands`, `TestExchangeRefusesMutatingCommands`, `TestEveryExportedMethodSendsAnAllowlistedCommand`, `TestFindQuotingRoundTrips`, `TestFindRefusesALineBreakOrNUL` and `TestFindWritesTheQuotedLine` pin it.
- **A cancelled command expires its deadline, and finishing the command clears it.** The cancel callback runs on another goroutine and `context.AfterFunc`'s stop does not wait for it, so `done` waits until the callback has set its deadline and then clears it. **Don't set an expired deadline after the command has returned, and don't keep that coordination on the client:** it holds no password. `TestCancelBesideAFinishedReplyDoesNotStickTheDeadline` pins it.
- **A password is never logged, printed, serialised or put in an error string.** The configuration keeps the values unexported. What is redacted is the whole value and, when it is MPD's `secret@permissions` (`src/Permission.cxx` splits on the first `@`), the secret before the `@` as well. A secret of four bytes or more is replaced wherever it occurs. A shorter one is replaced only as a whole token: the rune on either side is not a letter or a digit, so `_`, `/`, `.` and `-` are boundaries and a one-byte password does not rewrite a plain word such as `admin`. A problem or a path that would have contained one says `[redacted]`. The client does not store the password after `Dial`, and an `ACK` that echoes it comes back as `[redacted]`. A failed `Dial` returns no `Client`, so the `bufio.Reader` that read the ACK does not outlive the call. A password inside an `audio_output` block is that output's own and is not the client's. **Don't add a field, a log line or an error that carries the value, and don't echo a path that holds it.** `TestPasswordIsRedacted`, `TestPasswordSecretIsRedactedInAnIncludePath`, `TestShortPasswordRedactsWholeTokensOnly`, `TestShortSecretBoundaryIsALetterOrDigit`, `TestDialDoesNotKeepThePassword`, `TestHoldsSecretWalksContainers`, `TestWrongPasswordIsAnACKAndDropsTheSecret` and `TestOutputPlayerNeverPrintsAPassword` pin it. `holdsSecret` walks maps, arrays (including `[N]byte`), pointers and interfaces, so a later field of any of those shapes fails the test.
- **A path rule is one per library root, proved by `os.SameFile` and then by `find`.** MPD's `music_directory` comes from `mpd.conf` (`config` over TCP is refused). The root matches when it is that directory, or when exactly one top-level entry resolves to a real path that is the root or contains it, and `os.SameFile` agrees on `music_directory/<entry>/<rel>`. A same basename that is a different file is `unproven`, and so is more than one match. A Volumio root at `/media/NVME/music` under the `USB` link is `USB/NVME/music/`. A regular file in `music_directory` is not stat-ed; a directory, a symlink, or an entry of unknown type is. `find` then confirms at most 20 indexed paths of that root, evenly from the sorted list. A result is reused for about 60s, longer than the 500ms response cache, only when a lookup was available, the track read did not error, and no rule is `unchecked`, `mismatch` or errored. A change of music directory, roots, endpoint, conf or password drops it. An `unchecked` from a down daemon or an empty index is not kept. `proven` is a match every sample found, `mismatch` is a match a sample's lookup answered as not found, `unchecked` is no music directory, no lookup, no tracks, or a lookup that returned an error. An error is not a missing file. A multi-root scan stores `filepath.Base(root) + "/" + rel` and the strip prefix is that basename plus `/`; a track belongs to that root only when its stored path has that exact prefix. A single-root scan stores the path relative to the root with no basename prefix, the strip prefix is empty, and every indexed track belongs to that root. A case-folded first segment is not a member: the client strips the exact prefix. The strip and prepend prefixes are computed here and filled only on a match, including `unchecked` with no tracks, so the app swaps prefixes and does not re-derive them. **Don't prove a root by its basename, and don't ask `find` before a single SameFile match.** `TestProveRootsStates`, `TestProveRootsAmbiguousMatchIsUnproven`, `TestProveRootsVolumioLayout`, `TestDirEntrySkipsRegularFiles`, `TestPathRulesOutliveTheResponseCache`, `TestLookupErrorIsNotCached`, `TestUncheckedWithoutASessionIsNotCached`, `TestUncheckedWithNoTracksIsNotCached` and `TestPathRulesUseTheStoredRootPrefix` pin it.
- **`config` is permitted to a local socket only.** Over TCP, MPD 0.24 answers `ACK [4@0] {config} Command only permitted to local clients`, and `music_directory` then comes from the configuration file. **Don't treat that ACK as a daemon that is down, and don't expect `config` over TCP to name the library.** `TestConfigIsRefusedOverTCP` pins the reply.
- **`mpd.conf` is found in MPD 0.24.4's order, not `/etc` first** (`src/CommandLine.cxx` `ParseCommandLine`, `src/fs/glue/StandardDirectory.cxx` `GetUserConfigDir`, the Linux `USE_XDG` build): `$XDG_CONFIG_HOME/mpd/mpd.conf` when that variable is an absolute path of a directory that exists, and in that case `~/.config` is not also tried; otherwise `$HOME/.config/mpd/mpd.conf` when `$HOME` and `$HOME/.config` exist; then `$HOME/.mpdconf`; then `$HOME/.mpd/mpd.conf`; then `/etc/mpd.conf`. The Apple build's `~/Library/Application Support` is not this search. **Don't look in `/etc/mpd.conf` first, and don't try both XDG and `~/.config`.** A candidate that is a directory, a pipe, a socket or a device is skipped. A Windows cloud placeholder is `ModeIrregular` and is still a file. **Don't use `IsRegular` for that check.** `TestSearchOrderMatchesMPD`, `TestConfCandidateKeepsACloudPlaceholder`, `TestFindSkipsADirectory` and `TestFindSkipsAFifo` pin it.
- **An include is relative to the file that names it, bounded, and not a glob.** Depth 16, 32 files, no cycles, and a path that leaves the root is refused for `include` and `include_optional` alike; only a missing file is optional. A path that cannot be stat'd, or a file that cannot be opened, is reported as unreadable for both directives, and the host path is not added to the problem. MPD expands globs and does not bound the recursion; this reader does neither expansion nor unbounded recursion. A key this reader does not extract is ignored, so a newer file still yields the settings, where MPD itself would reject it. **Don't follow an include out of the root.** `TestIncludeCycleAndDepth`, `TestIncludeStaysInsideTheRoot` and `TestUnreadableIncludeIsReported` pin it.
- **The dial is the first socket the file names, else `127.0.0.1` and the port setting or 6600.** A socket is a `bind_to_address` whose first character is `/`, `~`, `@` or `$`. A TCP bind that embeds its own port (`localhost:6602`) is not what this dials. **Don't dial the address in a TCP bind.** `TestEndpointPrefersASocket` pins it.
- **`~` and `$` expand the way MPD's `ParsePath` expands a socket, for a flag and for the file alike, and an unexpanded endpoint is not dialled.** A leading `~` or `~/` is the home directory when that string is absolute; the directory need not exist. `~user` is refused: this reader does not call `getpwnam`. A leading `$NAME` or `$NAME/rest` is `HOME`, `XDG_RUNTIME_DIR`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` or `XDG_MUSIC_DIR` (`src/config/Path.cxx` `GetVariable`, `src/config/Net.cxx` `ServerSocketAddGeneric`). `XDG_RUNTIME_DIR` is used only when it is an absolute directory that exists, with no fallback. `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` fall back to `~/.config` and `~/.cache` when those directories exist. `$XDG_MUSIC_DIR` is the absolute value the caller passed; this reader does not parse `user-dirs.dirs`. A result that is not absolute, a variable that is unset, and a relative path are a problem and are not a TCP dial. The problem does not quote the endpoint, and the report's endpoint is left empty, so the path is nowhere in the report. **Don't dial `~/…` or `$…` as a path or as TCP, and don't store the path after a refusal.** `TestRuntimeDirSocketIsDialled`, `TestUnsetRuntimeDirIsNotDialled`, `TestUndiallableEndpointIsAbsentFromTheReport`, `TestTildeFlagExpandsBeforeDial`, `TestTildeWithoutHomeIsNotDialled` and `TestDialRefusesAnUnexpandedSocket` pin it.
- **A non-repeatable parameter keeps the last value.** MPD 0.24.4 `ReadConfigParam` (`src/config/File.cxx`) clears that option's list when the option is not repeatable, then adds the new value; `GetParam` (`src/config/Data.hxx`) returns the only element left. `bind_to_address` and `password` are the repeatable ones (`Templates.cxx`) and are appended. A second `resampler` block is the exception `ReadConfigBlock` throws for: this reader keeps the first and reports the second. **Don't keep the first value of `volume_normalization`, `replaygain` or `music_directory`.** `TestParseQuotingEscapesCommentsAndUnknownKeys` and `TestRepeatedParameterKeepsTheLast` pin it.
- **A block that is not closed does not absorb the next block.** `config_read_block` reads names and quoted values until `}`; a nested block keyword is not a quoted value, and EOF before `}` throws (`File.cxx`). This reader closes the open block with a problem and starts the next one, so a `format` on the next output cannot land on the previous one. A key repeated inside a block is a problem and the first value stands, for every key, including one this reader does not extract (`config_read_name_value` throws on the second; `Block.cxx` `GetBlockParam` returns the first). **Don't merge two blocks into one.** `TestAnUnclosedBlockDoesNotAbsorbTheNext` and `TestARepeatedKeyInsideABlockIsAProblem` pin it.
- **The greeting and the reply are framed exactly as MPD writes them.** The greeting is `OK MPD ` plus the version (`src/client/New.cxx` `GREETING`). A reply ends on a line that is exactly `OK`, or exactly `ACK ` plus the bracket form (`doc/protocol.rst`). A `binary: N` line is followed by N bytes and a newline (`src/client/Response.cxx` `WriteBinary`); those bytes are not lines. A line whose key is `binary` but whose size is missing, malformed or over the cap is a framing error in both readers, not a pair. **Don't trim a greeting or an `OK`, don't treat a newline inside a binary chunk as the end of the reply, and don't keep a bad `binary:` line as a pair.** `TestGreetingAndReplyFramingIsExact`, `TestBinaryChunkDoesNotEndTheReply`, `TestMalformedBinarySizeIsAFramingError` and `FuzzReadReplyMatchesParseReply` pin it.
- **`ReadHost` resolves both the root and the file before it computes the logical path.** `filepath.Abs` does not follow a symlink, so on macOS a root of `/private/var` and a file under `/var` (or the reverse) would otherwise store a path that walks out with `../`. **Don't compute the logical path from the unresolved names.** `TestReadHostResolvesBothSidesBeforeTheLogicalPath` pins it.
- **The player is named from the files the distribution installs, and nothing is executed.** Volumio is both `/volumio` and `/data/configuration`, and its version is `VOLUMIO_VERSION`, `VOLUMIO_BUILD_VERSION` and `VOLUMIO_BUILD_DATE` in `/etc/os-release`. That file is read as os-release(5): a line whose first non-space character is `#` is a comment; a double-quoted value unescapes `\\`, `\"`, `\$` and `` \` `` and keeps a `#` inside the quotes; an unquoted value ends at whitespace or `#`. moOde is `/usr/local/bin/moodeutl` (moode-player's `usr/local/bin/moodeutl`); the version is the `<li>Release: ` line in `/var/www/footer.min.php`, falling back to `footer.php` (the footer markup is `<li>Release: 10.2.2 2026-05-31</li>`). A `Release:` in a comment or a script string is not that line, and the value ends at `<`, `"`, `;`, `)` or the end of the line. Volumio wins when both are present. Otherwise the software is MPD, and only when a configuration was read or a daemon answered. **Don't run `moodeutl`.** `TestDetectMoodeAndVolumioWins`, `TestOSReleaseFollowsTheShellQuoting` and `TestMoodeFooterFallback` pin it.
- **On Linux, `bridge output player` reads the host unless `--root` names another tree.** `--mpd` replaces only the endpoint and `--conf` only the configuration path. Detection still uses `/`. When `--conf` is empty the search for `mpd.conf` uses `/` too. Off Linux the command reads only what a flag names, and with none of them it refuses before touching `/`. A `--root` search does not use the process's home. The home and the XDG variables are filled from the environment only when the command is not reading a `--root` tree, so a `~` or `$` in `--mpd` or in the file can expand. **Don't skip detection because `--mpd` or `--conf` was set, and don't scan the host off Linux.** `TestMPDAndConfFlagsDoNotSkipTheHost` pins it.
- **`mpd.Report`'s JSON is `bridge output player --json`'s diagnostic shape**, every key present, a list `[]`, and `configPermitted` null when `config` was not attempted. It is not a wire type. **Don't encode an `mpd` type from an `internal/api` handler.**
