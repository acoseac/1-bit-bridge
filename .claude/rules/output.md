# The box as an audio output (`internal/alsa`, `internal/mpd`, `bridge output`, the loopback track route, the player checklist)

The bridge's own player (B470: its PCM format and decoders, DSD and ALAC containers, the ALSA PCM backend and the streaming sink) is in `player.md`, which loads with this file for the player's code.

The bridge as an output: on a Linux box with a DAC and MPD, it reports the DAC and a live reading of what the DAC receives, so the app's Signal Path can show it. Step one (2026-10-19) reads `/proc` and adds `bridge output dac`. Step two (the same day) finds the player and reads how MPD is set: `internal/mpd` is a read-only client, `internal/mpd/conf` reads `mpd.conf`, and `bridge output player` prints both. Step 2b adds `output.mpd` (`auto`, `on` or `off`) and `GET /v1/outputs` when that resolves on and the host is Linux. Step 2c (2026-10-21) adds the loopback track route the MPD beside the bridge fetches from (`internal/dlna/loopback.go`, `cmd/bridge/output_loopback.go`), `mpd.loopbackBaseURL`, and the Player / DAC / Music / Phone checklist (`internal/outputcheck`, `cmd/bridge/output_checklist.go`) that `bridge doctor` and the console print from one source. Step three (B3, 2026-10-22) adds the live reading, `GET /v1/outputs/{id}/reading` (`internal/api/outputs_reading.go`, `cmd/bridge/output_reading.go`), and the bridge's verdict on the format it receives (`internal/signalpath`; since round 3, the owner's two levels: never bit-exact for an MPD output). The record is in `ops/engineering-log.md` under those dates.

## The ALSA reader, the MPD client and `bridge output`

- **`owner_pid` in a substream's `status` is a THREAD id**: the thread that opened the PCM, which for MPD is its output thread (`output:alsa`, not `mpd`). **Name and Tgid come from one read of `/proc/<tid>/status`.** When Tgid is that tid, the process name is the same Name; otherwise it is the Name line of `/proc/<tgid>/status`. **`comm` is only the fallback when that status has no Name line. Never read `/proc/<owner_pid>/comm` as the process's name**, and report both names.
- **An owner nobody can name is unknown, never an error**: a missing or unreadable `/proc` entry (hidepid, a thread that exited) or an `owner_pid` of 0 (outside this pid namespace) leaves that name null, and the reading is whole. **Don't turn it into a problem or a failed read.**
- **A card whose devices cannot all be enumerated says so** (`CardReading.Partial`, B470 PR 4a2 round 2): its directory or a `pcmNp` directory that could not be listed, or the type of a `pcmNp` or `subM` entry a listing named that could not be read, for any reason but its absence, and its problems say which. An entry that is not there, gone since the listing that named it, is the card or the device going, as a missing file is, and never Partial. The mark is in memory only (`json:"-"`): the `--json` shape is pinned (`TestOutputDACJSONHasOneShapeInEveryState`), and the problems say it there. `binding.Observer` makes the player's inventory partial on it (`player.md`): until then a card whose PCM directory could not be listed read as having no endpoint. **Don't read a listing that failed as a card or a device with nothing in it.** `TestAProcCardSaysWhenItsDevicesCannotAllBeListed` pins it.
- **The reader takes its roots and carries no build tag**, so its tests read the captured trees in `internal/alsa/testdata` on all three CI OSes. Only `bridge output dac` refuses, and only the host's own tree, off Linux; `--proc-root` reads a tree anywhere. **Don't move the reader behind `//go:build linux`.**
- **In `cmd/bridge` the host's `/proc` and `/sys` are named in one place, `hostTrees` (`output_host.go`), and no test reads them** (B470 PR 4a round 5). Serve's and `bridge doctor`'s outputs builders hand `api.LocalOutputsConfig` its `Cards` as `hostTrees.cards`, since a nil `Cards` falls back to the host's `/proc`; `bridge output dac`, `pcm-test`, and `dac inspect` and `bind` fall back to `hostTrees` on Linux when no flag names a tree. The suite's TestMain points it at two empty directories before any test runs and never again. The localOutputs gate opens the builders' path on Linux alone, and for `auto` only where MPD is found, so a test that reached it with the host's trees passed on macOS and read the host on CI's Linux leg (`TestDoctorPassesWithNoRoots`). The player's hotplug watcher (`startPlayerHotplug`) reads the box through `hostTrees` too, and the sweep refuses a `hotplug.Config` built without its `Observe`, which falls back to the host's trees (B470 PR 4a2). **Don't name the host's trees in `cmd/bridge` outside `hostTrees`, build an ALSA reader without its root, or leave an outputs builder without its `Cards` or the hotplug watcher without its `Observe`.** `TestTheDoctorsOutputsBuilderReadsNoHostTree`, `TestTheSuiteReadsEmptyTreesForTheHosts` and `TestOnlyHostTreesNamesTheHostsTrees` pin it.
- **A parser ignores a key it does not know, and reports a key it knows whose value does not parse**, a second line of a key the kernel prints once (the first value stands), and a block the kernel always prints whole that arrives without one of its lines (a file cut short). It never guesses a value: what did not parse is null. Kernels add lines, so a strict parser fails on the next kernel; a guessing one shows the app a reading nothing proved.
- **One altset is one `Format:` line and, since Linux 5.1, one `Bits:` line** (`sound/usb/proc.c` `proc_dump_substream_formats`, v4.19 through v6.17). The Format line is every name in the altset's bitmask, space-separated, in `snd_pcm_format_name` order; `SPECIAL` is `SNDRV_PCM_FORMAT_SPECIAL`, kept in that list, and a DSD format is any `DSD_` name wherever it sits. A second Format line is a repeated key, not another format. **Bits has been printed for UAC1 and UAC2 alike only since 5.1** (c7a13264918b); a stream without it is unknown, never cut short. Format, Channels and Rates have been printed since v4.19 and a missing one of those is still cut short.
- **Every read stays inside the roots it was given.** Each root is opened once per reading as a `tree` (an `os.Root`), and every read, listing and stat goes through its descriptor after `resolve` has followed the path's links one at a time inside it, so a link swapped in after that look is refused at the open (B470 PR 4a round 3: the reader checked with `EvalSymlinks`, then opened the pathname again). `pcmNp` and `subM` count when the stat says they are directories, and a stream file only when its target is a regular file, so a symlink to either is the target; a link out of the tree, absolute or climbing past the root (`errOutsideRoot`), still counts, so its read reports the refusal, and is never opened, so `--raw` cannot print it. The kernel's `/proc/asound/<id>` link to `cardN` is relative, stays inside the root and still reads. **Don't follow a link out of the tree, and don't check a path and then open it by name.** `TestReaderRefusesAFileThatLeavesTheRoot`, `TestReaderRefusesALinkSwappedInAfterItsCheck` and `TestReaderFollowsSymlinkedPCMAndSubdirectories` pin it.
- **`--watch` compares readings without what moves on every read while audio plays** (`steadyView`: the buffer pointers, delay, avail, the timestamps, the measured rate and the packet size). **Don't add a moving value to the comparison**: it would print once a second for as long as anything plays.
- **The `alsa` types' JSON is `bridge output dac --json`'s diagnostic shape**, every key always present and every list `[]`. A `/v1` route that serves a reading wraps it in a DTO under `internal/api`, as the wire-type discipline in `wire.md` requires; **don't encode an `alsa` type from a handler.**
- **The fixtures are captures, byte for byte**, pinned to LF in `.gitattributes`; `testdata/README.md` names each synthetic file. A new case comes from `bridge output dac --raw` on a real box. **Never edit a captured file**: add a synthetic case beside it.
- **DAC capabilities come from every playback altset, and a native DSD rate is the altset's frame rate times the format's width.** `DSD_U32_*` is ×32, `DSD_U16_*` is ×16, `DSD_U8` is ×8. A DSD format whose width is not one of those is listed and adds no rate. PCM rate and bit depth come only from a format matching `S` or `U` plus digits (`S24_3LE` is 24); a DSD altset's `Bits` line and its frame rates are not PCM. **Don't read the running `hw_params` as what the card can do, and don't invent a multiplier.** `TestCapabilitiesFromTheIFiCapture`, `TestCapabilitiesFromTheSynthetic768AndDSD512`, `TestCapabilitiesTable` and `TestNativeDSDRate` pin it. `pcm768-dsd512` is the synthetic stream: 768 kHz PCM and DSD512.
- **An ALSA device string resolves to a card only when it names one.** `hw`, `plughw`, `plug` and `front` may name an index or a card id (`hw:N`, `hw:N,D`, `hw:CARD=ID`, `hw:CARD=ID,DEV=D`, and the same with `plughw:`), and the id match is exact: two cards with that id do not resolve. Any other name is a PCM looked up in `etc/alsa/conf.d/*.conf` and then `etc/asound.conf`, inside the config root beside the proc root the reader was given. A name defined more than once, in one file or across them, including a `pcm.!name` for a name already defined, is unresolved. A `pcm` stanza that is not `pcm.NAME { … }` or `pcm.!NAME { … }`, including a brace-nested `pcm { … }` and a dotted assignment such as `pcm.out.card 2`, makes the file unusable. A second `type`, `card`, `device` or `slave` in one block is unresolved. `slave.pcm`, dotted or a `slave { pcm }` block, is followed through `empty` and `plug` only, at most 8 hops, until a `type hw` whose `card` is an id or an index. A slave whose name contains `:` is a device string (`hw:`, `plughw:`, and the same plugins as a direct device), never a PCM block of that name. A `ctl` block and a `defaults` assignment are skipped, and `;` and `,` are separators. Inside a `pcm.NAME { … }` block, `@args`, `@func`, `$VAR` and any nested block this parser does not model make that name opaque: the chain that reaches it is unresolved, and the rest of the file still counts. The same directives inside a skipped `ctl` or `defaults` block are skipped with it. At the top level, `@hooks`, `@args`, `@func` and an include (`<…>`) make the whole configuration unresolved, and so does a file that is present but cannot be read. One such file makes the whole configuration unresolved: definitions from the other files are not used. A missing file does not. A string accepts only `\"`, `\\` and `\'`; any other escape makes the file unusable. A `dmix`, `softvol`, `rate`, `route`, `multi`, plugin, hook, include, cycle, a longer chain, a file this parser does not understand, or a missing file stays unresolved, and the route then lists each USB card with `isMPDsOutput` null. A resolved card that is in `/proc/asound/cards` is listed alone with `isMPDsOutput` true. **Don't guess a card.** `TestResolveALSADevice`, `TestResolveOutputDeviceVolumioChain`, `TestResolveOutputDevice`, `TestDuplicatePCMIsUnresolved`, `TestDuplicateKeyIsOpaque`, `TestSlaveDeviceString`, `TestNonPCMStanzaIsSkipped`, `TestStringEscapeIsOnlyQuoteOrBackslash`, `TestUnparsedFileDropsTheRest`, `TestUnmodeledPCMStanzaIsUnusable`, `TestAtDirectiveInsideSkippedBlock`, `TestPluginPCMDoesNotSpoilTheFile`, `TestResolveOutputDeviceVolumioChain` and `TestVolumioPCMNamesTheDAC` pin it.
- **A dead MPD session is dropped and dialled once more in that build.** The cached client is reused only for the same endpoint and password, so a config change dials fresh. A non-context error from `status` or `find` closes it; a cancelled caller does not. **Don't keep serving `unknown` and `mismatch` off a connection MPD has already closed.** `TestDeadMPDSessionIsRedialed`, `TestDeadFindRedialsOnce` and `TestSessionFollowsTheEndpoint` pin it.
- **`GET /v1/outputs` answers only when `output.mpd` resolves on and the host is Linux.** `on` is on even when nothing greets; `auto` is on when a configuration was read or a daemon greeted; anything else, and every host that is not Linux, is `404` `local_outputs_not_supported` and no `localOutputs` flag. The DTOs live in `internal/api`. **Don't encode an `alsa` or `mpd` type from the handler.** `kind` is the open string `mpd`; a client ignores a kind it does not know. `mpd` is a pointer, present only for kind `mpd`, and omitted for kind `bridge`. `mpd.version` is empty when the daemon is down. Each unresolved candidate card is its own element, with the same `mpd` and `pathRules` and a different `id` and `dac`. `isMPDsOutput` is `true` or `null`, never `false`. `mpd.loopbackBaseURL` is the loopback track route's base URL (`http://127.0.0.1:<port>`), present only while the route serves: additive, so a client decodes it as optional. `addresses` are the advertised LAN IPs on which MPD's port greets `OK MPD`; loopback and link-local (`fe80::/10`, `169.254/16`) are never listed, the probes run together, and each probe has one deadline covering the dial and the read. None means `reachableFromLAN` false. The id is the SHA-256 of the data-directory identity (`OutputIdentity`, the same directory `deriveDLNAUDN` hashes, without the friendly name), the MPD endpoint, the card's ALSA id and its USB id, never the TLS fingerprint, the library name or the card index, and it is stable across restarts and certificate renewals. The session opens on the first call and closes about 60s after the last call, on a clock the route takes as `Now` and `AfterFunc`. The idle close does not run while a build is in flight; that build re-arms the timer when it finishes. One build runs at a time, on a context detached from the caller with its own deadline (about 15s), and a success is reused for 500ms. A build that hits that deadline is not cached, and a caller that disconnects does not cancel the waiters. **A build that panics completes its flight all the same** (`Response`'s deferred completion, B473 B3 round 4): with an error, logged without the panic's value (`logOutputPanic`) and never cached, so the next call builds afresh; until then a panic there (a `find` that panicked, which drops the session) left the flight open, and every later call, the console's checklist with them, waited out its own context. **Don't dial from `/v1/health`:** the flag's auto probe is a separate short cache, keyed on one read of `output.mpd`, endpoint, conf and password, and it runs on a context detached from the caller so a cancelled request does not store a miss. Concurrent callers for one key share that in-flight probe. A result whose own deadline fired is not stored. **The inspection runs on a goroutine of its own** (`inspectBounded`, B473 B3 rounds 2 and 3): it reads `mpd.conf` and the player's files, which a dead mount holds whatever the context says, so it is waited for until its deadline and `outputProbeGrace` (100 ms, for a dial that ends with its context) more. One that has not returned by then, a probe's that finds one still running (no probe starts a second), and one that panics (logged) are abandoned: no report and no verdict (the loopback route's bullet), since a file that hangs is no evidence MPD has gone. `TestLocalOutputsGate`, `TestOutputsJSONKeepsEveryKey`, `TestOutputKindIsOpen`, `TestOutputsLANAddresses`, `TestLANProbesRunTogetherAndSkipLinkLocal`, `TestGreetDeadlineCoversDialAndRead`, `TestOutputsCacheAndIdle`, `TestProbeCacheFollowsTheConfig`, `TestProbeCachesTheConfigurationItProbed`, `TestProbeMissesShareOneFlight`, `TestProbeDeadlineIsNotCached`, `TestCancelledProbeIsNotCached`, `TestIdleCloseSkipsABuildInFlight`, `TestOutputsOneBuildInFlight`, `TestCancelledCallerDoesNotSpoilTheBuild`, `TestBuildDeadlineIsNotCached`, `TestOutputsIDStableAcrossRestarts`, `TestOutputIDIgnoresTheCardIndex`, `TestIsMPDsOutputIsTrueOrNull`, `TestAProbeThatHangsEndsTheReadingInTime`, `TestAnInspectionThatNeverReturnsIsNoVerdict` and `TestAPanicInTheOutputsBodyClosesItsFlight` pin it.
- **`output.mpd` is `auto`, `on` or `off`, and only `on` is a bridge with no library.** `auto` (the default, and what an unset value means) is on when Volumio or moOde is installed, a configuration was read, or a daemon greeted (`mpd.Report.Found`), which Validate does not decide. The same gate starts the loopback track route, answers it on every request, and shows the player checklist, so `off` is the opt-out from all of it, and an explicit `on` or `off` wins over detection (`TestLocalOutputsActiveStartsTheLoopbackRoute`, the unset rows included). A loopback bridge still requires a library root, so a default install does not become output-only. A public bridge (`Config.IsPublic()`) may have no roots: Validate warns and does not fail. `on` with no roots loads, `bridge doctor` does not fail it, and serve starts and serves no tracks. Endpoint, conf and password are the overrides `bridge output player` takes. **Don't log the password or put it in an error, and don't dial from Validate.** `TestOutputOnlyConfigHasNoRoots`, `TestOutputModeRejectsAnythingElse`, `TestAutoStillRequiresARoot`, `TestOutputOnlyBridgeStarts` and `TestDoctorPassesWithNoRoots` pin it.
- **The loopback track route serves this bridge's own tracks to the MPD beside it, on 127.0.0.1 and ::1 and no other address, while `output.mpd` resolves on** (B473 B2c, decision 2). It is the DLNA listener's file route, `/dlna/file/{trackID}`, the same track id and the same serving half (`serveOpenedFile`), on a listener of its own (`dlna.LoopbackServer`), whether or not the DLNA server is enabled, with no SSDP, ContentDirectory, artwork, silence, rendition, routed track, listing or authentication. The port is `output.loopbackPort`, 7791 unless set: MPD keeps the URLs in its queue across a bridge restart, so it is fixed; 0 is a kernel pick for tests. ::1 is optional and the base URL names 127.0.0.1. Serve starts it the first time the localOutputs gate answers true (asked once at boot, and `OnActive` on every later true answer, for an MPD that appears after boot), binds once (a taken port is one Warn and `StartErr` for the checklist), and stops it before the store closes. **Every request in between asks whether `output.mpd` still resolves on** (`LoopbackConfig.Enabled`, which serve wires to `api.Server.LocalOutputsActiveNow`): `off` refuses at once, `on` serves, and `auto` follows the gate's most recent answer, whatever its age or the configuration it was for, so the listener stays up and a request is refused with `404 not_serving`. `Active` records auto's answer under its lock every time it has a verdict (`answerAuto`): from a probe it stored, a probe whose inspection returned past its own deadline and was not stored, the cache, or another caller's probe it waited on. A probe whose inspection was abandoned (it never returned, one still ran, or it panicked) is no verdict, number 0 like a caller that stopped waiting, and records nothing (B473 B3 round 3). Each verdict is numbered under the lock as it is produced (a cache hit at its read, a probe at its completion, the number saved into the flight before `done` closes so every waiter carries it), and a caller records one only when its number is newer than the recorded one's, and is answered with the newest recorded verdict: a caller that carried an older verdict out of the lock never overwrites a newer one (the tests park a caller between its verdict and its record with `beforeRecord`). A caller that stopped waiting on another caller's probe has no verdict of its own (number 0): it is answered with the gate's last answer and records nothing, so a request that ends while a probe runs cannot turn the route off. The route's answer is a read of that record (`localOutputs.activeNow`, false before the first) that never probes, dials or greets MPD, never runs `OnActive`, and never waits on MPD: every holder of the lock releases it before any I/O. A nil `Enabled` serves nothing, and with no output reader wired every reader of the config reads the empty one (`outputConfig`). `Stop` closes a stream still running when its context ends: `http.Server.Shutdown` returns at the context and leaves an active connection open. Before it says whether it serves, the handler refuses a remote address that is not loopback whatever the bind (`loopback_only`), a Host other than `127.0.0.1`, `[::1]` or `localhost` with any port or none (`loopback_host_only`: a page that re-pointed its own name at 127.0.0.1, DNS rebinding, reaches the route from loopback under that name; an empty Host too), and a request that carries `Forwarded`, `X-Forwarded-For`, `X-Forwarded-Host` or `X-Real-IP`, even empty (`forwarded_request`). A proxy on the host that strips all four and forwards to the port is the owner's own configuration, which nothing in the request tells from MPD. It then refuses anything but GET and HEAD of exactly one id (a segment below it, a rendition included, is `not_found`), and a routed track. A file is served only when its links resolved (`fsutil.ResolveLinks`) lie inside a configured root (`fsutil.IsUnderAny`) before the open, the path resolved again after the open is still inside, and the file that opened is the file `os.Root` reaches below that root (`sameFileInRoot`, which follows a link only while it stays inside and never an absolute one). A path that does not begin with the root byte for byte is refused. A configured root's own path and its ancestors are trusted as the owner's (a root that is a link is followed wherever it points); the route defends everything below a root. Refusals are the route's typed JSON (`loopback_only`, `loopback_host_only`, `forwarded_request`, `not_serving`, `method_not_allowed`, `not_found`, `not_a_file`, `outside_library`, `internal`), not `/v1` codes, so PROTOCOL.md's error table does not list them. **Don't serve a rendition, a routed track, a listing or a second route there; don't drop the remote-address check because the bind is loopback; don't decide whether the route serves only when its listener starts, or from the stored probe rather than the gate's last answer, don't let an older verdict overwrite a newer one, don't take an abandoned inspection for a verdict, and don't let a request dial MPD to decide it; don't answer a Host that is not loopback or a forwarded request; don't open before the first containment check; and don't confirm the opened file with `os.Stat`, which follows a link swapped in after the check.** Each window is reproduced by parking the request in it (the handler's `beforeOpen`, `afterOpen`, `beforeConfirm`). `TestLoopbackRouteRefusesARemoteThatIsNotLoopback`, `TestLoopbackRouteServesOnlyWhileOutputIsOn`, `TestTheLoopbackRouteAsksTheGateWithoutDialling`, `TestTheRouteFollowsAnExpiredProbeThatFoundMPD`, `TestTheRouteStopsOnAnExpiredMissAfterATrue`, `TestActiveNowIsTheGatesLastAnswer`, `TestACallerThatStopsWaitingGetsTheGatesLastAnswer`, `TestAnInspectionThatNeverReturnsIsNoVerdict`, `TestActiveNowReadsTheConfigLikeTheProbe`, `TestAnOlderCacheVerdictNeverOverwritesANewerOne`, `TestAWaiterNeverRecordsAnOlderVerdict`, `TestServeAsksTheGateOnEveryLoopbackRequest`, `TestLoopbackRouteAnswersOnlyALoopbackHost`, `TestLoopbackRouteRefusesAForwardedRequest`, `TestLoopbackRouteServesTheFileUnaltered`, `TestLoopbackRouteConfinesToTheLibraryRoots`, `TestLoopbackRouteRefusesALinkSwappedAfterTheCheck`, `TestLoopbackRouteRefusesADirectorySwappedAfterTheCheck`, `TestLoopbackRouteRefusesADirectorySwappedBackAfterTheOpen`, `TestLoopbackRouteRefusesASwapInEveryWindow`, `TestLoopbackRouteListsNothing`, `TestLoopbackRouteServesNoVariantAndNoRoutedTrack`, `TestLoopbackRouteRefusesOtherMethods`, `TestLoopbackRouteRefusesWhatIsNotAFile`, `TestLoopbackServerBindsOnlyLoopback`, `TestLoopbackServerStopsWithTheServer`, `TestOutputLoopbackPort`, `TestOutputsCarryTheLoopbackBaseURL`, `TestServeServesItsTracksOnLoopbackWhileOutputIsOn` and `TestServeStartsNoLoopbackRouteWhileOutputIsOff` pin it.
- **The player checklist is four lines from one source: `internal/outputcheck` judges, `cmd/bridge`'s `outputChecklist` gathers, and `bridge doctor`, the console's doctor and the dashboard print it** (B473 B2c). - **The MPD connection stays lazy: asking the localOutputs gate dials no session, and a one-shot builder closes its session at once** (B473 B2c, decision 4).
