# The box as an audio output (`internal/alsa`, `internal/mpd`, `bridge output`)

The bridge as an output: on a Linux box with a DAC and MPD, it reports the DAC and a live reading of what the DAC receives, so the app's Signal Path can show it. Step one (2026-10-19) reads `/proc` and adds `bridge output dac`. Step two (the same day) finds the player and reads how MPD is set: `internal/mpd` is a read-only client, `internal/mpd/conf` reads `mpd.conf`, and `bridge output player` prints both. Neither step changes a wire format, a route or a config key. The record is in `ops/engineering-log.md` under that date.

- **`owner_pid` in a substream's `status` is a THREAD id**: the thread that opened the PCM, which for MPD is its output thread (`output:alsa`, not `mpd`). **Name and Tgid come from one read of `/proc/<tid>/status`.** When Tgid is that tid, the process name is the same Name; otherwise it is the Name line of `/proc/<tgid>/status`. **`comm` is only the fallback when that status has no Name line. Never read `/proc/<owner_pid>/comm` as the process's name**, and report both names.
- **An owner nobody can name is unknown, never an error**: a missing or unreadable `/proc` entry (hidepid, a thread that exited) or an `owner_pid` of 0 (outside this pid namespace) leaves that name null, and the reading is whole. **Don't turn it into a problem or a failed read.**
- **The reader takes its roots and carries no build tag**, so its tests read the captured trees in `internal/alsa/testdata` on all three CI OSes. Only `bridge output dac` refuses, and only the host's own tree, off Linux; `--proc-root` reads a tree anywhere. **Don't move the reader behind `//go:build linux`.**
- **A parser ignores a key it does not know, and reports a key it knows whose value does not parse**, a second line of a key the kernel prints once (the first value stands), and a block the kernel always prints whole that arrives without one of its lines (a file cut short). It never guesses a value: what did not parse is null. Kernels add lines, so a strict parser fails on the next kernel; a guessing one shows the app a reading nothing proved.
- **One altset is one `Format:` line and, since Linux 5.1, one `Bits:` line** (`sound/usb/proc.c` `proc_dump_substream_formats`, v4.19 through v6.17). The Format line is every name in the altset's bitmask, space-separated, in `snd_pcm_format_name` order; `SPECIAL` is `SNDRV_PCM_FORMAT_SPECIAL`, kept in that list, and a DSD format is any `DSD_` name wherever it sits. A second Format line is a repeated key, not another format. **Bits has been printed for UAC1 and UAC2 alike only since 5.1** (c7a13264918b); a stream without it is unknown, never cut short. Format, Channels and Rates have been printed since v4.19 and a missing one of those is still cut short.
- **Every read stays inside the roots it was given.** `pcmNp` and `subM` count when `Stat` says they are directories, and a stream file only when its target is a regular file, so a symlink to either is the target. A path that resolves outside its root is refused and not opened, so `--raw` cannot print it; the kernel's `/proc/asound/<id>` link to `cardN` stays inside the root and still reads. **Don't follow a link out of the tree.**
- **`--watch` compares readings without what moves on every read while audio plays** (`steadyView`: the buffer pointers, delay, avail, the timestamps, the measured rate and the packet size). **Don't add a moving value to the comparison**: it would print once a second for as long as anything plays.
- **The `alsa` types' JSON is `bridge output dac --json`'s diagnostic shape**, every key always present and every list `[]`. A `/v1` route that serves a reading wraps it in a DTO under `internal/api`, as the wire-type discipline in `wire.md` requires; **don't encode an `alsa` type from a handler.**
- **The fixtures are captures, byte for byte**, pinned to LF in `.gitattributes`; `testdata/README.md` names each synthetic file. A new case comes from `bridge output dac --raw` on a real box. **Never edit a captured file**: add a synthetic case beside it.
- **The MPD client sends only the allowlist, and `exchange` is the only writer.** The commands are `status`, `stats`, `outputs`, `replay_gain_status`, `currentsong`, `config`, `commands`, and `password` solely as the argument `Dial` sends when the caller already holds one. There is no method that starts, stops or seeks playback, and none that edits the queue or the database. **Don't add a command, or a write, that `exchange` does not check first**; a refusal is `mpd: command refused` and names neither the command nor the argument. `TestAllowlistIsExactlyTheReadCommands`, `TestExchangeRefusesMutatingCommands` and `TestEveryExportedMethodSendsAnAllowlistedCommand` pin it.
- **A password is never logged, printed, serialised or put in an error string.** The configuration keeps the values unexported. What is redacted is the whole value and, when it is MPD's `secret@permissions` (`src/Permission.cxx` splits on the first `@`), the secret before the `@` as well. A secret of four bytes or more is replaced wherever it occurs. A shorter one is replaced only as a whole token: the rune on either side is not a letter or a digit, so `_`, `/`, `.` and `-` are boundaries and a one-byte password does not rewrite a plain word such as `admin`. A problem or a path that would have contained one says `[redacted]`. The client does not store the password after `Dial`, and an `ACK` that echoes it comes back as `[redacted]`. A failed `Dial` returns no `Client`, so the `bufio.Reader` that read the ACK does not outlive the call. A password inside an `audio_output` block is that output's own and is not the client's. **Don't add a field, a log line or an error that carries the value, and don't echo a path that holds it.** `TestPasswordIsRedacted`, `TestPasswordSecretIsRedactedInAnIncludePath`, `TestShortPasswordRedactsWholeTokensOnly`, `TestShortSecretBoundaryIsALetterOrDigit`, `TestDialDoesNotKeepThePassword`, `TestHoldsSecretWalksContainers`, `TestWrongPasswordIsAnACKAndDropsTheSecret` and `TestOutputPlayerNeverPrintsAPassword` pin it. `holdsSecret` walks maps, arrays (including `[N]byte`), pointers and interfaces, so a later field of any of those shapes fails the test.
- **`config` is permitted to a local socket only.** Over TCP, MPD 0.24 answers `ACK [4@0] {config} Command only permitted to local clients`, and `music_directory` then comes from the configuration file. **Don't treat that ACK as a daemon that is down, and don't expect `config` over TCP to name the library.** `TestConfigIsRefusedOverTCP` pins the reply.
- **`mpd.conf` is found in MPD 0.24.4's order, not `/etc` first** (`src/CommandLine.cxx` `ParseCommandLine`, `src/fs/glue/StandardDirectory.cxx` `GetUserConfigDir`, the Linux `USE_XDG` build): `$XDG_CONFIG_HOME/mpd/mpd.conf` when that variable is an absolute path of a directory that exists, and in that case `~/.config` is not also tried; otherwise `$HOME/.config/mpd/mpd.conf` when `$HOME` and `$HOME/.config` exist; then `$HOME/.mpdconf`; then `$HOME/.mpd/mpd.conf`; then `/etc/mpd.conf`. The Apple build's `~/Library/Application Support` is not this search. **Don't look in `/etc/mpd.conf` first, and don't try both XDG and `~/.config`.** `TestSearchOrderMatchesMPD` pins it.
- **An include is relative to the file that names it, bounded, and not a glob.** Depth 16, 32 files, no cycles, and a path that leaves the root is refused for `include` and `include_optional` alike; only a missing file is optional. MPD expands globs and does not bound the recursion; this reader does neither expansion nor unbounded recursion. A key this reader does not extract is ignored, so a newer file still yields the settings, where MPD itself would reject it. **Don't follow an include out of the root.** `TestIncludeCycleAndDepth` and `TestIncludeStaysInsideTheRoot` pin it.
- **The dial is the first socket the file names, else `127.0.0.1` and the port setting or 6600.** A socket is a `bind_to_address` whose first character is `/`, `~`, `@` or `$`. A TCP bind that embeds its own port (`localhost:6602`) is not what this dials. **Don't dial the address in a TCP bind.** `TestEndpointPrefersASocket` pins it.
- **`~` and `$` expand the way MPD's `ParsePath` expands a socket, for a flag and for the file alike, and an unexpanded endpoint is not dialled.** A leading `~` or `~/` is the home directory when that string is absolute; the directory need not exist. `~user` is refused: this reader does not call `getpwnam`. A leading `$NAME` or `$NAME/rest` is `HOME`, `XDG_RUNTIME_DIR`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` or `XDG_MUSIC_DIR` (`src/config/Path.cxx` `GetVariable`, `src/config/Net.cxx` `ServerSocketAddGeneric`). `XDG_RUNTIME_DIR` is used only when it is an absolute directory that exists, with no fallback. `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` fall back to `~/.config` and `~/.cache` when those directories exist. `$XDG_MUSIC_DIR` is the absolute value the caller passed; this reader does not parse `user-dirs.dirs`. A result that is not absolute, a variable that is unset, and a relative path are a problem and are not a TCP dial. The problem does not quote the endpoint, and the report's endpoint is left empty, so the path is nowhere in the report. **Don't dial `~/…` or `$…` as a path or as TCP, and don't store the path after a refusal.** `TestRuntimeDirSocketIsDialled`, `TestUnsetRuntimeDirIsNotDialled`, `TestUndiallableEndpointIsAbsentFromTheReport`, `TestTildeFlagExpandsBeforeDial`, `TestTildeWithoutHomeIsNotDialled` and `TestDialRefusesAnUnexpandedSocket` pin it.
- **A non-repeatable parameter keeps the last value.** MPD 0.24.4 `ReadConfigParam` (`src/config/File.cxx`) clears that option's list when the option is not repeatable, then adds the new value; `GetParam` (`src/config/Data.hxx`) returns the only element left. `bind_to_address` and `password` are the repeatable ones (`Templates.cxx`) and are appended. A second `resampler` block is the exception `ReadConfigBlock` throws for: this reader keeps the first and reports the second. **Don't keep the first value of `volume_normalization`, `replaygain` or `music_directory`.** `TestParseQuotingEscapesCommentsAndUnknownKeys` and `TestRepeatedParameterKeepsTheLast` pin it.
- **A block that is not closed does not absorb the next block.** `config_read_block` reads names and quoted values until `}`; a nested block keyword is not a quoted value, and EOF before `}` throws (`File.cxx`). This reader closes the open block with a problem and starts the next one, so a `format` on the next output cannot land on the previous one. A key repeated inside a block is a problem and the first value stands, for every key, including one this reader does not extract (`config_read_name_value` throws on the second; `Block.cxx` `GetBlockParam` returns the first). **Don't merge two blocks into one.** `TestAnUnclosedBlockDoesNotAbsorbTheNext` and `TestARepeatedKeyInsideABlockIsAProblem` pin it.
- **The greeting and the reply are framed exactly as MPD writes them.** The greeting is `OK MPD ` plus the version (`src/client/New.cxx` `GREETING`). A reply ends on a line that is exactly `OK`, or exactly `ACK ` plus the bracket form (`doc/protocol.rst`). A `binary: N` line is followed by N bytes and a newline (`src/client/Response.cxx` `WriteBinary`); those bytes are not lines. A line whose key is `binary` but whose size is missing, malformed or over the cap is a framing error in both readers, not a pair. **Don't trim a greeting or an `OK`, don't treat a newline inside a binary chunk as the end of the reply, and don't keep a bad `binary:` line as a pair.** `TestGreetingAndReplyFramingIsExact`, `TestBinaryChunkDoesNotEndTheReply`, `TestMalformedBinarySizeIsAFramingError` and `FuzzReadReplyMatchesParseReply` pin it.
- **`ReadHost` resolves both the root and the file before it computes the logical path.** `filepath.Abs` does not follow a symlink, so on macOS a root of `/private/var` and a file under `/var` (or the reverse) would otherwise store a path that walks out with `../`. **Don't compute the logical path from the unresolved names.** `TestReadHostResolvesBothSidesBeforeTheLogicalPath` pins it.
- **The player is named from the files the distribution installs, and nothing is executed.** Volumio is both `/volumio` and `/data/configuration`, and its version is `VOLUMIO_VERSION`, `VOLUMIO_BUILD_VERSION` and `VOLUMIO_BUILD_DATE` in `/etc/os-release`. That file is read as os-release(5): a line whose first non-space character is `#` is a comment; a double-quoted value unescapes `\\`, `\"`, `\$` and `` \` `` and keeps a `#` inside the quotes; an unquoted value ends at whitespace or `#`. moOde is `/usr/local/bin/moodeutl` (moode-player's `usr/local/bin/moodeutl`); the version is the `<li>Release: ` line in `/var/www/footer.min.php`, falling back to `footer.php` (the footer markup is `<li>Release: 10.2.2 2026-05-31</li>`). A `Release:` in a comment or a script string is not that line, and the value ends at `<`, `"`, `;`, `)` or the end of the line. Volumio wins when both are present. Otherwise the software is MPD, and only when a configuration was read or a daemon answered. **Don't run `moodeutl`.** `TestDetectMoodeAndVolumioWins`, `TestOSReleaseFollowsTheShellQuoting` and `TestMoodeFooterFallback` pin it.
- **On Linux, `bridge output player` reads the host unless `--root` names another tree.** `--mpd` replaces only the endpoint and `--conf` only the configuration path. Detection still uses `/`. When `--conf` is empty the search for `mpd.conf` uses `/` too. Off Linux the command reads only what a flag names, and with none of them it refuses before touching `/`. A `--root` search does not use the process's home. The home and the XDG variables are filled from the environment only when the command is not reading a `--root` tree, so a `~` or `$` in `--mpd` or in the file can expand. **Don't skip detection because `--mpd` or `--conf` was set, and don't scan the host off Linux.** `TestMPDAndConfFlagsDoNotSkipTheHost` pins it.
- **`mpd.Report`'s JSON is `bridge output player --json`'s diagnostic shape**, every key present, a list `[]`, and `configPermitted` null when `config` was not attempted. It is not a wire type. **Don't encode an `mpd` type from an `internal/api` handler.**
