# The bridge's player (B470: PCM format and decode, DSD and ALAC containers, the ALSA PCM backend, the streaming PCM sink, the player's DAC binding, the hotplug watcher, the player's state owner and queue, the player's backend, the player inside bridge serve and its library resolver)

The bit-exact OpenHome player inside the bridge (B470), PR by PR. These sections moved verbatim from `output.md` on 2026-10-22, when that file neared its budget; `output.md` keeps the box-as-output rules (the ALSA reader, the MPD client, `bridge output`, the loopback route, the player checklist) and loads beside this file for the player's code.

## Player PCM format and decode (B470 PR 1a)

- **PCM is stereo signed integer, 16/24/32 valid bits only.** No downmixing, truncation, resampling, floating intermediates, ReplayGain, normalization, dither or crossfade. Native DSD is produced by the DSF and DFF demuxers (the DSD section below); DoP is a shape for a later PR. **Don't add a transform that changes samples.**
- **Content inspection chooses the decoder**, never the file extension or the library index. Lossy containers (MP3, AAC, Ogg/Opus/Vorbis) are refused with a typed reason; ALAC in M4A opens the ALAC decoder (the ALAC section below), and DSF and DFF open the DSD demuxers below. `Open` returns a `Source`: a `Decoder` for PCM, a `DSDDecoder` for DSD. **Don't decide support from a path suffix.**
- **Supported containers:** integer FLAC via `mewkiz/flac` frame parse only (16/24-bit; 32-bit FLAC is refused because that library still treats frame sample-size code 111 as reserved); integer WAV including validated `WAVE_FORMAT_EXTENSIBLE` PCM (chunks may precede `fmt `); integer AIFF and AIFF-C `NONE`/`sowt`. Float WAV/AIFF, 8/12-bit, mono and multichannel are refused. **Don't call `flac.NewSeek`:** its PICTURE parse and uncancellable `makeSeekTable` are unbounded. Metadata is walked with size caps (large bodies skipped by seek); seeking uses an optional bounded SEEKTABLE or a cancellable forward scan that accumulates `BlockSize` (never `SampleNumber()` × short final block).
- **WAVE_FORMAT_EXTENSIBLE valid bits are MSB-aligned** in the container: shift right by `containerBits-validBits` before sign-extend. **Don't mask the low bits** — that throws away the true sample. AIFF/WAV reads stay inside the declared data/SSND region; incomplete frame sizes and rates that are not exact positive supported integers are refused (AIFF 80-bit rates must be normalised). Header chunk bodies and non-audio scans are bounded; WAV and AIFF share `pcmRegion` for the linear payload read (64 KiB chunks, `ctx` after each read, seek-back to `posFrame` on cancel or I/O error so a retry cannot skip audio into a trailing `LIST`/`ID3` chunk, capped by the declared data/SSND end). Per-sample unpack stays in each decoder (WAV LE + MSB-aligned valid bits; AIFF BE / sowt LE). A short mid-stream read may return `n > 0` with a truncated Refusal on the same call. ID3-prefixed files open via an offset seeker (v2.4 footer flag adds 10 bytes); post-ID3 sniffing is the full container path. SEEKTABLE points after the target or with overflow-sized fields are ignored. MP4 sniff walks container/`meta` FullBox children with depth and box caps, never raw `moov` substrings; box sizes are compared as `uint64` against `uint64(len(buf))` before any int conversion (a high-bit extended size must not panic). A `moov`/`moof` read capped at 4 MiB, or cut short by the end of the file, sets a truncated flag so a box that crosses the cut is a scan boundary (partial descent into containers, then stop), not `unsupported_layout` that would discard an earlier `alac`/`mp4a` (PR 1c: a cut AAC file is `lossy_refused`, a cut ALAC file reaches the ALAC demuxer, which refuses it as truncated; `TestSniffKeepsTheCodecWhenTheFileEndsInsideMoov`). **Don't alter a sample; refuse with a typed reason.**
- **ALSA PCM packers preserve every source bit under lossless widening:** `S16_LE`, `S24_3LE`, `S24_LE` (4-byte container, low 24 significant), `S32_LE` from 24-bit (shift left 8, low byte zero). Container width alone does not establish precision.
- **Golden hashes come from reference tools**, never from the bridge decoder. `scripts/player-pcm-goldens/generate.py` produces committed fixtures; ordinary tests do not run it. Private corpus files under `~/medialibtest-formats/` stay untracked. In-range golden seeks must return exactly `Channels` samples — `(0, EOF)` must not pass.

## Player DSD containers (B470 PR 1b)

- **Canonical native DSD is stereo, channel-separated bytes, bit 7 earliest** (`format.NativeDSD`). **Don't convert DSD to PCM, don't reverse a byte the container declared MSB-first, and don't round a DSD count up by adding before dividing.** → History-rules-player.md
- **Accepted:** **Don't decode DST, don't take the first two channels of a multichannel file, and don't skip `FVER` as an unknown chunk.** → History-rules-player.md
- **The sample count ends DSF audio, never the data size.** The final block group is zero-padded to 4096 per channel; the data chunk must hold every block group the sample count needs, or the file is `truncated_or_corrupt` at open. The `DSD ` chunk's metadata pointer and total size are never used, so ID3 metadata is never read as audio. Before the sound data, DFF chunks other than `FVER` and `PROP` (`COMT`, `MANF`, and `DIIN` or `ID3 ` where a writer puts them there) are skipped by their sizes plus the pad byte after an odd body (§2.3), in the form's walk and in `PROP`'s; `PROP` must precede the sound data. The walk ends at the sound chunk, so a chunk after it, where `DIIN` and `ID3 ` usually sit, is never read. `CMPR` is read only for its four-byte compressionType, so a `CMPR` whose size counts the name's pad (20 bytes for "not compressed", the form `internal/dsdtone` writes) opens like §3.2.3's 19-byte one (`TestDFFCMPRWithItsNamePadInsideStillOpens`). **Don't follow the DSF metadata pointer.**
- **PR 1a's invariants hold for DSD.** **Don't bound a size by adding it to a position.** **Don't add a second linear reader beside `linearRegion`.** → History-rules-player.md
- **DSD goldens are an independently specified pattern**. **The DFF goldens give both chunk walks an odd chunk before the sound data**. **Don't make every chunk of a DFF golden even.** → History-rules-player.md

## Player ALAC in M4A (B470 PR 1c)

- **ALAC is decoded by saprobe-alac's packet decoder alone, behind the package's own demuxer and checks.** The bridge builds the module at v1.0.0-rc3 (Apache-2.0), the first release with the fix for the over-read the bridge reported (the next bullet), and only `NewPacketDecoder` and `DecodePacket` are called, through the `alacPackets` seam. Its container path, `NewDecoder`, panics on malformed configurations, allocates from untrusted counts and ignores edit lists (Codex's B470 evaluation, of 1b6eb83). The library's defects, with a minimal input each, are in `ops/upstream/saprobe-alac.md`. Adding the module raised `golang.org/x/text` to v0.43.0 by minimum version selection. **Don't call `alac.NewDecoder`, and don't hand the library a configuration or a packet the checks below did not pass.**
- **saprobe-alac v1.0.0-rc3 checks every entropy code against the packet's own length (GHSA-g66f-c97f-q276, the bridge's report), so `go.mod` requires it with no `replace` and no copy in `third_party/`** (2026-10-23). **Don't pin a saprobe-alac older than v1.0.0-rc3, and don't bring back a patched copy for a defect rc3 fixes; a later version must pass the over-read and hostile-packet tests in `internal/player/decode`.** → History-rules-player.md
- **The M4A demuxer (`m4a.go`, `alac.go`) reads boxes by seeking, never moov whole**. **Every table count is checked against its box with `fits` before anything is allocated for it, every box against its parent by subtraction (PR 1b round 3), and a constant-size stsz's count against the mdat bytes the file holds.** **Don't load moov whole, don't allocate from a count before `fits`, and don't add a table reader that skips it.** → History-rules-player.md
- **The cookie is validated before the library is constructed.** **afconvert writes 16 bits, 44100 Hz and 2 channels in every ALAC sample entry, mono and 24-bit/96 kHz included, so the cookie decides; the entry's channel count only refuses a writer that puts the stream's own count there, as FFmpeg does.** **Don't compare the entry's sample size or rate with the cookie, and don't construct the library before the cookie passes.** → History-rules-player.md
- **Each packet's element header is read before the library decodes it**: a channel pair first (for an END first the library returns a whole packet of silence and no error, and for a single-channel element one channel), unused bits clear, a shift of at most two bytes, the frames stts gives it (the frame length, or a partial packet's count), no compressed 32-bit pair without a shifted byte (its 33-bit residuals make the library read past its padding), no compressed 16-bit pair with a shift (the library reads the shifted bytes and its 16-bit output drops them, so the frame decodes to its residuals alone with no error; Apple's and FFmpeg's encoders shift only above 16 bits; Codex's review of #1300), and a kb of at least 1 for a compressed packet. The decoded length must be the packet's frames. **Don't drop a check because the library also makes it: its silent cases are why they are here, and don't patch `WriteStereo16` for the shift: refuse the packet.** `TestALACCorruptPacketHeadersRefused` and `TestALACShiftedBytesIn16BitPacketRefused` pin it.
- **A panic in the library is recovered as a `truncated_or_corrupt` refusal, the last resort**. **Don't remove the recover, and don't let a recovered packet return samples.** → History-rules-player.md
- **An edit list's one edit is honoured**: presentation starts at its media time and lasts the frames its duration covers whole, floor(duration × rate ÷ movie timescale) in 128-bit arithmetic, never past the media's end. afconvert's own decode of an edited file presents the same frames (it floored durations whose fractions were .1, .5 and .7); it also ignores the duration when the media time is 0, which this decoder does not copy. Several edits, an empty edit (media time −1), a negative media time, a rate other than 1, a zero duration, a media time at or past the media's end, an edit that covers no whole frame, and an edit with no mvhd timescale are refused. **Don't round an edit's duration up, and don't drop its duration.** `TestALACGoldensMatchPattern` on the edited golden, `TestALACEditListVersion1`, `TestALACEditPastTheEndClipsAtTheMedia` and `TestALACEditListsRefused` pin it.
- **Seeks are exact**: the index holds every packet's offset and the stts runs, a seek decodes the packet that holds the frame and drops the frames before it, and the end of the presentation is a seek target. Every packet read seeks to its own offset, so a cancel or an I/O error leaves nothing to undo; a cancel during a packet's read returns none of that packet; a failed seek sticks until a successful `Seek`. A file cut inside a packet returns the whole packets before the cut, then a truncated refusal. `TestALACGoldensExactSeek`, `TestALACCancelThenRetryNoGap`, `TestALACIOErrorThenRetryNoGap` and `TestALACTruncatedMidPacket` pin it.
- **ALAC goldens are an independently specified pattern that afconvert encodes.** **Don't derive an ALAC expectation from the decoder.** → History-rules-player.md
- `FuzzALACOpen` fuzzes the whole path, and a recovered library panic is a refusal there; `BRIDGE_ALAC_FUZZ_STRICT=1` makes it a failure, for runs that look for library panics no check prevents. It then opens each file again with `overrunOracle` in the library's place, which decodes every packet the library decodes twice more with bytes appended to it: a packet decoded from past its end decodes differently, and fails the target in either mode. `FuzzALACCookie` fuzzes the cookie validation alone, and checks that what it accepts gives a library decoder that decodes a one-frame escape packet exactly.

## Player ALSA PCM backend (B470 PR 2a)

- **The kernel interface is pinned and checked, never vendored.** **Don't vendor asound.h, don't change an ioctl number or a structure without the other, and don't add a definition the probe does not print.** → History-rules-player.md
- **The kernel's PCM protocol is 2.0 and at least 2.0.15.** Another major or minor is refused whatever its micro (`SNDRV_PROTOCOL_INCOMPATIBLE`); below 2.0.15 (Linux 5.6) is refused as a qualification bound, not an ABI one: every kernel the owner's hardware runs is newer, and the oldest maintained line, 5.10, carries it. `swParams.proto` sends the pinned header's version. **Don't raise the floor to the pinned header's version, which would refuse every kernel from 5.6 to the pin.** `TestOpenRefusesAProtocolBelowTheFloor` pins it.
- **An endpoint is two numbers.** **Don't add a way to name an endpoint by string, and don't open anything but the node an Endpoint names.** → History-rules-player.md
- **Busy is the kernel's exclusive open, and the bridge leaves the holder alone.** The non-blocking open returns EBUSY at once for a node another process holds (MPD playing): `ReasonBusy`, naming the endpoint. `bridge output pcm-test` then names the holding thread and process from `/proc/asound` (`internal/alsa`, read only). **Never stop MPD, signal it or touch its configuration, and don't wait for a busy device.** `TestOpenNamesABusyEndpoint` and `TestOutputPCMTestNamesTheHolderOfABusyDevice` pin it.
- **Rate, channels and format are exact; the buffer geometry may vary.** **Don't accept a committed value other than the one asked for, and don't read a committed interval any other way.** → History-rules-player.md
- **An underrun is an xrun, never silence.** SW_PARAMS sets the stop threshold to the buffer size, so the buffer running empty stops the stream; the silence threshold and size are 0, so the kernel fills nothing; the stream starts once the buffer is full; a waiting writer wakes a period at a time. **Don't set a stop threshold above the buffer size or ask the kernel to fill silence.** `TestOpenCommitsExactlyWhatWasAsked` pins it.
- **A write goes on where it stopped, waits bounded, and types how it ended.** **POLLERR alone is not a disconnect**. **Don't type POLLERR without asking the state, and don't recover an xrun in Write.** → History-rules-player.md
- **A cancel ends a wait at once.** **Don't poll in time slices to notice a cancel, and don't close the eventfd under a started callback.** → History-rules-player.md
- **Go memory reaches the kernel only for the length of a call.** Every pointer-bearing ioctl goes through `ioctlOn`, which keeps its argument alive across the call, and PAUSE, whose int is the argument itself, through `ioctlValue`; `xferi.buf` is an `unsafe.Pointer` field, so the samples it points at stay alive and move with a stack; nothing is mmapped. **Don't keep a buffer's address in a uintptr, don't pass the kernel a Go pointer except through ioctlOn, and don't mmap the status, control or data areas without a design for their lifetime.**
- **Stopping is bounded, and the node is closed once.** **Don't wait for a drain without a deadline, and don't let a refused open keep the node.** **Don't drain without reading the state first.** → History-rules-player.md
- **The device logic is portable; only the kernel seam is Linux's.** **Don't move the device logic behind the build tag, and don't build `linuxSys` for an architecture whose layout the `alsa-abi` job does not check.** → History-rules-player.md
- **`bridge output pcm-test` is the hardware harness, run by hand.** **Don't make the tone louder than -30 dBFS, don't list the command in `bridge output`'s usage, and don't call it from the server.** → History-rules-player.md

## Player streaming PCM sink (B470 PR 2b)

- **One writer goroutine owns the Device, fed through a store preallocated at open.** **Don't touch the Device from another goroutine, don't allocate on the producer's path, don't size the store past MaxRingBytes, and don't publish frames without asking the sink's state under the same lock.** → History-rules-player.md
- **With nothing to write, the writer watches the stream.** **Don't wait for frames without watching the stream.** → History-rules-player.md
- **The position is what the kernel establishes, never more.** Content played is the frames written minus what the kernel holds: STATUS's delay while the stream runs or drains, the driver's own delay included; all of the run before the stream starts, where STATUS reports a delay of 0; and appl_ptr less hw_ptr while it is paused, where the delay is 0 too. A run is what was written since the last PREPARE, which the pointers count from, recorded as content and silence, so zeros never count. The position never goes back, never passes `Written`, ignores a reading it cannot use (a negative delay, pointers that disagree with what was written), and does not move while the sink is paused, released, stopped by an xrun or done. A writer blocked inside a partial write has not counted those frames yet, so `Written` may trail the kernel's appl_ptr by part of a period. Interpolating between measurements is the engine's, and stays at or under this. **Don't read STATUS's delay outside RUNNING and DRAINING, don't count silence as content, and don't let the position go back or run ahead of a measurement.** `TestSinkPositionIsWrittenMinusWhatTheKernelHolds`, `TestSinkPositionIgnoresAReadingItCannotUse` and `TestSinkPausesWithZeros` pin it.
- **A pause is the kernel's PAUSE when the setup offers it, zeros otherwise, and nothing at all before the stream starts; after `ReleaseAfter` (30 s) the device is released.** `PauseAuto` pauses with PAUSE when `Params.CanPause` (SNDRV_PCM_INFO_PAUSE) and with zeros on ENOSYS; `PauseKernel` refuses hardware without PAUSE at open; `PauseZeros` always writes zeros. A pause by PAUSE stops at once, its buffer kept; a pause by zeros keeps the stream running, so the sound stops after what is queued has played, at most the hardware buffer; a stream still filling is paused by writing nothing. A pause by zeros reserves two segments of the run's record (its silence and the content after it) and is refused, typed, when they are not free. The release measures, closes the device (DROP, HW_FREE, close), and takes back from what was written the content frames the DAC had not played; `Resume` opens the same endpoint with the same parameters and writes them first. A refused reopen (busy, gone, no permission) comes back typed and the sink stays released, its position kept. A release whose unplayed frames the store no longer holds ends the sink rather than skip them. **Don't pause with DROP, don't release without taking back the frames not played, and don't reopen anything but the same endpoint and parameters.** `TestSinkPausesWithTheKernelsPause`, `TestSinkPausesAStreamThatHasNotStartedByWritingNothing`, `TestSinkPausesWithZeros`, `TestSinkReleasesAPauseAfterThirtySeconds` and `TestSinkResumeAfterAReleaseTypesWhatRefusesIt` pin it.
- **PAUSE's int is the ioctl's argument itself.** **Don't pass PAUSE a pointer, and don't put an integer in an unsafe.Pointer.** → History-rules-player.md
- **An xrun is reported and counted, never concealed, and recovered only when asked.** An underrun stops the sink (`SinkXrun`) with its error, and until `Recover` `Write` refuses frames and `Pause`, `Resume` and `Drain` answer with the xrun's error, so a caller that recovers on an xrun recovers whichever call found it (#1303's review: pcm-test's `--recover` gave up on an xrun the writer's wait had found before its Drain, which was answered `bad_state`). `Recover` alone issues PREPARE and plays on from the next content frame; a sink the xrun stopped while paused (zeros that came too late) stays paused on the prepared stream, writing nothing until `Resume`, and its release stays due when the pause began. Every xrun counts in `Position.Gaps` for the sink's life, and the last eight are kept in `Stats().Gaps`: the content frame where the stream stopped, the frames the store held (none lost), what found it (`write`, `wait`, `status`, `pause`, `resume` or `drain`), and when it was noticed and recovered. The kernel stops a stream once its pointer reaches the last frame written, so those frames count as played; what the DAC was sent between the underrun and the stop is the driver's, and the sink claims nothing about it. **Don't PREPARE without a Recover, don't reset the count, don't write a frame twice or skip one to cover a gap, and don't let Recover end a pause.** `TestSinkReportsAnXrunAndRecoversOnlyWhenAsked`, `TestSinkCountsEveryGapAndKeepsTheLastFew`, `TestSinkDrainReportsAnUnderrunBeforeIt`, `TestSinkAnswersCommandsAtAnXrunWithTheXrun` and `TestSinkRecoverKeepsAPause` pin it.
- **Drop is immediate; Drain plays out and stays pausable until the kernel's own drain; the end is typed, and the device closes once per open.** `Drop` measures, closes the device and stops the sink. `Drain` refuses further frames and writes out the lookahead with Pause and Resume still working (a paused drain waits for the resume, release and reopen included), then runs `Device.Drain`, bounded by the buffer's time and two seconds, during which the sender lets only a Drop through: an interrupted Device.Drain drops the stream and cuts off the end. The Drain's own context ending drops the stream, and reaches that Drain's waits alone: its callback cancels a wait only while its Drain is under way, so one that runs late, after the Drain was answered, leaves the next Drain's kernel drain alone, and `waitContext` looks at the drain's context under the lock the callback cancels under, so a cancel that comes between the writer's look at the drain and its next wait is never lost (#1303's review). A Drain is answered once the sink no longer counts it under way, so a Recover sent the moment a Drain reports an xrun is taken (a stress run of those tests found it refused). A disconnect, a suspend, a stall or the end of the sink's life context ends it (`SinkEnded`), typed; every later call gets that reason, and Drop and Close do nothing. **Don't let a command other than Drop interrupt the kernel's drain, don't let a Drain's cancel reach a wait that is not its Drain's, don't answer a Drain before its state is settled, and don't close a device twice.** `TestSinkDropIsImmediate`, `TestSinkDrainEndsEarlyOnACancelOrADrop`, `TestSinkCommandsFollowTheState`, `TestSinkLastBufferDrainsUninterrupted`, `TestSinkEndsOnADisconnectOrASuspendAndClosesOnce`, `TestSinkWriteWaitsWhileTheStoreIsFullAndItsCancelEndsTheWait`, `TestSinkCancelUnderLoadDropsAndClosesOnce`, `TestSinkAnAnsweredDrainsCancelLeavesTheNextDrainAlone`, `TestSinkAPausedDrainsCancelIsNotLost` and `TestSinkTakesRecoverAsSoonAsADrainReportsAnXrun` pin it.
- **A panic on the sink's writer ends the sink typed (`ReasonPanicked`), its device closed, and answers whatever waited on the writer; a node a panic comes to between its open and a sink taking it is closed** (B523). **Don't take the sink's lock on the writer but through `lockW`, answer the command under way twice, keep a node no sink took, or report a writer panic during Resume as a resumable device refusal.** → History-rules-player.md
- **Gapless is one transport, and the sink only answers.** `Transport` is the kind, rate, channels, ALSA format and valid bits packed (24 bits in S32_LE is not 32); `Transport.Join` and `Sink.Next` answer whether the next track follows with nothing between, naming each difference otherwise. A gapless track's frames are written straight after the last ones: no drain, reopen, PREPARE or silence. A different transport needs a drain, a sink opened for it and a refill, an honest gap. The engine (PR 4b) decides and keeps track boundaries as content frames; a boundary reaches the DAC when `Position.Played` passes it. **Don't put anything between two tracks of one transport, and don't join two of different transports.** `TestSinkJoinsCompatibleTracksBackToBack` and `TestTransportJoinNamesWhatDiffers` pin it.
- **The fake kernel plays, and only as far as the test lets it.** With `model` set, it consumes the frames written since PREPARE at the committed rate as its clock moves; the clock moves only in a poll that waits, and only by the simulated time the test grants (`grant`, `play`), so a test decides how much plays between its steps; under `free` a wait for room or for a drain's end takes the time it needs, and a wait for an error condition alone (a paused writer, a watching one) still waits for a grant. `heard` is what the DAC consumed across every open, and `when` closes a channel when a condition on the fake holds, checked inside each call. A test that reads what the sink made of a reading waits for the writer's next wait (`filledAndIdle`, `starved`), never for the STATUS call itself, whose condition holds before the sink has applied the reading (#1303's Linux race: `Played` read 14200 for 15000, reproduced every time with the writer parked between the reading and its use). `starved` counts a poll only while its context has not ended, since the producer's frames end a watch without waiting for it to leave; `revoke` takes back a grant a later wait must not play on; the fake's poll prefers a cancel that comes with a grant, as `linuxSys.poll` does; `advanceNow` wakes a waiting poll and `advanceUnwatched` does not, the moment before the kernel's wake-up reaches the writer, which a command or frames may beat; `onNow` and `atNow` act at a read of the clock. The sink's own seams (`sinkSeams`) are the producer's two hooks, `producerWaits` and `producerPublishes`, and `afterFunc`, which registers what a Drain's context ending runs, so a test can hold a callback back or the writer where it lets go; `commanded`, called on the sender's goroutine once a command is handed to the writer, is the fake's `OnCommand`. No sink test sleeps or polls; the one real-time timer is a watchdog (`-watchdog`, a minute) that turns a hang into a failure. **Don't add a sleep or a polling loop to these tests, don't move the fake's clock outside a poll, a grant, `advanceNow` or `advanceUnwatched`, and don't wait on the STATUS call to read the position.**
- **`bridge output pcm-test` drives the sink for the PR 2b gate.** **Don't lower a file's level, don't play a file without `--ack-full-level`, don't stop MPD, don't sum frames of different rates, don't multiply a frame count by a second's nanoseconds, don't stop a run by dropping its sink alone, don't take a refusal for the run's failure before asking whether the sink's state changed since, and don't take a descriptor with `Fd`.** → History-rules-player.md

## Player output binding (B470 PR 4a)

- **`output.player` is the player's block, `OutputConfig.Mode` stays MPD's, and `Config.PlayerEnabled(goos)` is the player's predicate**: off by default, Linux only, never public. **A block that does not read, or is refused, turns the player off with a logged reason and never fails the load**: `UnmarshalYAML` never errors and keeps an unread block as written (`Save` writes it back, `Unread` says why), an alias to an anchor outside it as a copy of what it names (`keepable`: past 1024 copied nodes or 32 aliases deep the block is not kept, and its reason says a save drops it); `Problem` refuses field by field and quotes a value only when it is one of the words its field knows: anything else, a number included, is "that value", and a key it does not take "that key". This release takes `dsdMode` off, `allowDoP` false, `mixer` `{type: none, control: null}` (a scalar `mixer` is refused with a hint), `pauseReleaseSeconds` 1 to 3600 (30), ids of four hex digits alone or after `0x` (kept lowercase), and each binding with its own fields only. Resampling, rate, software volume, normalization and DSD-to-PCM keys, and a card, ALSA id or bus number in `device`, are refused by name. A LAN not up yet is `lan_unavailable`, never a refusal. **Don't fail the load over the block, quote a value in a reason unless it is a word its field knows, save an alias whose anchor the save does not write, add a setting that changes samples, or make Mode answer for the player.** Under `dsdMode: off` PR 4b refuses a DSD track. `TestAnInvalidPlayerBlockTurnsOffThePlayerAndNothingElse`, `TestEveryPlayerRefusal`, `TestASerialInTheWrongFieldIsNeverQuoted`, `TestAnUnreadBlockWithAnAliasSavesAFileThatLoads`, `TestAnUnreadBlockWhoseAliasesCannotBeCopiedIsNotKept`, `TestThePlayerIsLinuxOnlyAndNeverPublic` and `TestValidateReadsNoHardware` pin it.
- **Validate logs why the player is off once each time the reason changes, never at every Load and save** (2026-10-22, backlog B505). It runs on every Load and on every save that validates a clone first (the console's PATCH, the UPnP-upstream writer, init), and wrote the same line each time for a block that had not changed. `logPlayerOff` keeps the reason last seen, the process's, under a mutex (saves can validate at once; Validate still writes no field of its receiver), and writes the line when the reason differs; no reason (a player that runs, or one simply off) clears it, so the same reason coming back is written again. Once per process was rejected: it hides a problem that comes back, and a second after the first. ## Player hotplug watcher (B470 PR 4a2)

- **The source hears the kernel, and only the kernel.** **Don't join group 2, trust a port id other than 0, read past a message's buffer, wait for the watcher, read on past a cancel, or open anything a uevent names.** → History-rules-player.md
- **One goroutine per watch takes every reading, one at a time, on absolute deadlines.** A burst is read once quiet for 300 ms and never later than 2 s after its first event; the periodic reading comes every 10 s; an overflow with no window open is read at once; a changed binding at once; a retry after its backoff; a held answer at its bound (the next bullet); and once at start. A tick or an overflow inside an open window folds into it: every reading reads the whole box, so there is no partial reading to promote. The values are named once (`Timing`, `DefaultTiming`) on an injectable `Clock`, and a timer is armed at a deadline, never for a duration: a duration taken from one read of the clock and armed after another landed a whole fake-clock step late and lost the fire. A reading's own time is when it began (the snapshot's `Observed`, the hold's start); what it schedules runs from when it ended: the next follow-up and a failed reading's retry, and, after a reading that worked (its queued events taken), the periodic reading; every reading moves the periodic one on first, from its start, so one that returns early or fails leaves nothing due at once (round 3: from its start, a reading that took longer than the interval was followed at once by another, which may block as it did, as a read stuck on a USB device's lock does). **Don't take a reading off the watch's goroutine, read per event, read inside an open window, arm a timer for a duration, or schedule what follows a reading from when it began.** `TestABurstOfEventsIsOneReconcile`, `TestTheQuietWindowHolds`, `TestTheMaxDelayHolds`, `TestATickAndAnOverflowMidBurstFoldIntoItsReading`, `TestAnOverflowWithNoWindowReadsAtOnce`, `TestThePeriodicReadingCatchesAChangeNoEventAnnounced`, `TestThePeriodicReadingIsDueAPeriodAfterTheLastReadingEnds` and `TestTheFirstReadingIsGenerationOne` pin it.
- **The binding's answer is settled per card, held for a bounded time, and identity_transient is never latched.** A reading resolves the binding read from the live config on that reading (`Settings`, never captured at start) with `binding.Settled`: an unrelated transient card never holds the bound DAC's answer back, and a card that may be the bound unit, or under a port binding a card at the bound port (the Resolve bullet), holds it for three follow-ups 500 ms apart, after which it is published as it stands (the card transient, the binding `identity_transient`) with no more follow-ups until the next event, the start, an overflow, a changed binding or a periodic reading whose transient cards differ. Every window renews the follow-ups, so the hold is bounded apart from them: at most `Timing.holdMax`, `MaxDelay + FollowUps × FollowUpEvery` (3.5 s), from the first reading that held the answer (`heldSince`), with a reading due at that bound; from it the answer is published as it stands, and a publish ends the hold (round 2: an unrelated device sending an event every second held the answer, and subscribers read the gone card as available, for as long as it went on). The bound is judged when a reading ends, so one that began short of it and ended past it is published, at the time it read the box, and no other reading starts at once (round 3: judged at its start, that reading was held again, and the bound, past by then, started another, which may block as the first did). **Don't publish an unsettled answer while follow-ups remain and its bound has not come, hold one past its bound, judge the bound at a reading's start, hold back a settled one for an unrelated card, or keep a transient answer past the next reading.** `TestACardThatNeverSettlesIsPublishedTransientAfterTheFollowUps`, `TestAHeldAnswerIsPublishedWithinItsBoundWhileEventsGoOn`, `TestAReadingThatOutlastsAHeldAnswersBoundIsPublished`, `TestAnUnplugBesideAnUnrelatedTransientCardIsMissingAtOnce`, `TestATransientCardIsNotLatched` and `TestAChangedBindingForcesAReading` pin it.
- **The generation advances only on what a snapshot says changed, a fast replug is a change, and one replug is one generation.** The cards (index, ALSA id and name, state, unit, endpoints), a unit re-enumerated, the binding's state, unit, card, matches and endpoint, and the configured binding; never a card's `Why`, its directory, what a transient card's trees said, or a USB device with no card. A unit re-enumerated is the same unit (`SameUnit`) at another devnum (both read), another card number, or behind a removal the watcher saw (a remove or unbind whose DEVPATH is the card's directory, below it or above it): `Change.ReEnumerated` for the bound unit, `Card.ReEnumerated` for each. The source never waits, so the kernel's events queue while a reading runs, and a reading takes them before it publishes (`takeQueued`, those queued when it starts); when a removal among them reaches a card, the reading may show it (a replug that finished while it ran) or precede it, so it is set aside (`Stats.SetAside`) and the window those events opened reads the box again once they are quiet. Taking such a removal into the reading's own publish would claim a re-enumeration of a unit the reading showed unchanged. A reading is set aside once in a row, and never at a held answer's bound, which is judged when the reading ends, so the next is published with the removals in it (round 2: a replug's queued removals, taken after its publish, marked the unchanged replacement re-enumerated at a second generation, which would stop a play 4b started in between). **Don't compare units without their enumeration, advance the generation for a reading that changed nothing, publish a reading before taking what queued behind it, or set a reading aside twice in a row.** `TestAFastReplugOfTheBoundUnitIsAChange`, `TestAReplugThatQueuedDuringAReadingIsOneGeneration`, `TestAnUnplugThatQueuedDuringAReadingIsOneGeneration`, `TestAReadingIsSetAsideOnceInARow`, `TestAReadingAtAHeldAnswersBoundIsNeverSetAside`, `TestAReadingThatOutlastsAHeldAnswersBoundIsPublished` (a removal queued behind a reading that outlasts the bound), `TestAnUnchangedInventoryLeavesTheGenerationAlone`, `TestEachStateIsReachedFromAvailableAndBack`, `TestASecondUnitOfAUniqueModelIsAmbiguous`, `TestAHubOrAGoneControllerInvalidatesAPortBinding`, `TestAnotherUnitAtTheBoundCardIsASwap` and `TestUnplugIsMissingAndReplugIsAvailableAndNothingElse` pin it.
- **A reading that failed, or is partial, publishes no answer.** Partial is either tree's reading not whole: a sysfs root, listing or root hub that could not be read, a listing a cap cut, a stopped reading, or a /proc card whose devices could not all be enumerated (round 2). The last snapshot stands, republished at its generation marked stale (`Stale`) and saying why, the failure reported once a run, and the next attempt backs off from 1 s, doubling, to 30 s, from when the failed reading ended; a reading that works clears it. A stale snapshot is never grounds to start playback. **Don't invent a state from a reading that failed or was cut, or retry without a backoff.** `TestAReadErrorKeepsTheLastSnapshotStale`, `TestAPartialReadingIsAFailure`, `TestACardWhoseDevicesCannotBeListedIsAFailure` and `TestARetryIsDueItsBackoffAfterAFailedReadingEnds` pin it.
- **The feed is the serve's, its snapshots immutable, its mailboxes one slot each.** One `Feed` per serve: the generation starts at 1 and only grows, across a disable and re-enable, beside a random instance id; disabling publishes `disabled`, with no cards and the source off. A health change (stale, the source's mode) republishes the snapshot at its generation with its generation's `Change`. Every accessor copies, a port binding's port included (`Resolution.Port`, a `usbid.Port` whose segments and chain are slices; round 4: the port-binding fix added it, and the copy shared its slices with every consumer); a publish takes out what a subscriber has not received and puts the newest in, under the feed's lock, never waiting; nothing in a snapshot means play. Each generation is one INFO line, "player DAC: …" for a change of the binding's state or unit and "player hotplug: the inventory changed" (the cards by model) for the rest, naming the binding by its label and the unit by 4a's description, never a serial. **Don't wait on a consumer, hand out what a snapshot holds, restart the generation, or log a serial.** `TestAConsumerThatNeverReadsGetsTheNewest`, `TestASnapshotIsTheSameForEveryConsumer`, `TestEachConsumerGetsItsOwnCopyOfTheBoundPort`, `TestADisableAndReEnableKeepsTheGenerationIncreasing`, `TestEachStateChangeIsLoggedOnceWithoutASerial`, `TestSubscribersCanLeave` and `TestTheModeSaysNoEventsYetUntilTheKernelSpeaks` pin it.
- **A stop is bounded and abandons what is stuck.** The `Service` runs a watch while the live config enables the player and stops it when it does not; a stop cancels, waits at most `Timing.StopWait` (2 s) for the watch's goroutine and its source's, and abandons what has not stopped, saying which; the readers stop before their next card or file once the context ends, a read already started cannot be interrupted, and a reading an abandoned watch finishes is discarded by its context and by the feed's session, never published. The source's wait ends at once on a cancel (poll beside an eventfd, as `alsapcm`'s does), its drain looks at the cancel before every recv, and it closes the socket once. The watcher opens nothing under `/dev/snd` (the package's TestMain guards it). **Don't wait for a stuck read, publish from a stopped watch, or open a PCM node.** `TestShutdownJoinsTheWatcherWhileItWaitsForTheKernel`, `TestShutdownStopsAReconcileBetweenFiles`, `TestShutdownAbandonsAReadStuckInTheKernel`, `TestTheSourceStopsWhileTheKernelKeepsSending`, `TestEnablingThePlayerStartsTheWatcher`, `TestThePollingPathReadsOnTheClockAndSaysSo` and `TestThePlayersWatcherStopJoinsItsService` pin it.
- **The watcher's tests step a fake clock and never sleep.** A test advances the clock and waits on `Service.Updates` for a state (a count, the next deadline, `Stopping`); a stop's deadline is armed before the stop says it is stopping, so a test that advances on that sees it fire. A reading that events queue behind is reproduced by parking it before it reads the tree (`parkNextReading`) and queueing the kernel's events without waiting for the watcher (`queue`), never by racing a real one. A control that blocks a consumer fails by the test's watchdog: nothing on a test's way out takes the feed's lock, so it cannot hang the binary. **Don't add a sleep, a poll, or a deferred teardown that a blocked watcher can hold.**

## Player state owner and queue (B470 PR 4b1)

- **One owner goroutine runs every command, backend event and output report in turn, and a reply goes out after its step's snapshot.** `engine.Run` publishes an immutable `Snapshot` (accessors copy) after each step that changed anything, then sends that step's replies, so a caller reads its own change as its command returns. A command whose context ended before the owner admitted it does not run; after Run returns every method answers `closed` at once. Backend calls and file writes are goroutines of their own. A command's slices are copied before the owner sees them. A parked command waits only behind its own lane: an insert, a delete or a DeleteAll for a reservation write, at most `reserveTimeout` (5 s); Play and Pause for a transport call. Stop, output reports, maintenance and the modes never wait; a Stop or a stopping report answers the parked transport commands, none of which ran (a parked Pause nil, the rest `ReasonOvertaken`, or after a stopping report the output's reason; the Stop itself is never answered `ReasonOvertaken`), and EnterMaintenance every parked one. **Don't reply before the step's snapshot, don't block the owner on a call or a write, don't wait in a method without the done channel, don't park a command behind another lane's, and don't answer a command that never ran as one that did.** `TestAReplyComesAfterItsSnapshot`, `TestACommandCancelledBeforeAdmissionDoesNotRun`, `TestAfterRunReturnsEveryCommandIsClosed`, `TestSnapshotsAreImmutable`, `TestACancelledInsertKeepsNoneOfTheCallersSlices`, `TestAHungReservationWriteHoldsOnlyTheEditsThatNeedIt`, `TestAWaitingCommandWaitsOnlyForItsOwnLane`, `TestAStopDuringASlowOpenIsTakenAtOnce`, `TestAStopOvertakesTheTransportCommandsWaitingWithoutRunningThem`.
- **The generation (a random run ID and a count) moves on every controller-visible change and never on position, buffering or a starting session's first sound.** A mismatched or earlier-run `IfGeneration` is a typed conflict that changes nothing; EnterMaintenance checks it in the step that closes the engine. **Don't move it on a position.** `TestAnExpectedGenerationHoldsThroughSteadyPlayback`, `TestEachVisibleChangeMovesTheGeneration`, `TestAGenerationMismatchIsRefused`, `TestAGenerationFromBeforeARestartIsRefused`.
- **`Backend`'s doc is the contract 4b2 implements, and the fake enforces its first term: a session's Start comes only once the previous release is acknowledged.** Every session ends with a Release the engine asks for; a Release may reach the backend while its Start opens, or before that Start begins (each call is its own goroutine), and what that Start acquires is closed at once, never written to; an event counts only while its session is current; a call's context carries its deadline, on the engine's clock, and ends there with `context.DeadlineExceeded`, and so does a context derived from it (its `Done` is its own, so a child cannot attach to the base and end `Canceled`); a call past it releases its session, and an answer stamped at or past it is not taken, whichever message reaches the owner first. **Don't open before the last release is acknowledged, and don't take a late Start, event or answer for current.** `TestNoOpenOverlapsAnUnacknowledgedRelease`, `TestALateOpenIsClosedAndNeverWrittenTo`, `TestALateEventFromAnOldSessionIsDiscarded`, `TestMaintenanceDiscardsEarlierSessionsEvents`, `TestALateAnswerIsRefusedWhateverTheOrder`.
- **A release is confirmed or it is not.** Past `ReleaseTimeout` (2 s) unacknowledged it is `ReleaseUnconfirmed`, the pending intent is dropped, and Play, PlayID, PlayIndex, Next and Previous are refused until the late acknowledgement; a paused session's own release is held to PauseRelease plus ReleaseTimeout the same way; an acknowledged session is finished, so a deadline queued behind its acknowledgement changes nothing; an acknowledgement stamped at or past the deadline (`Events.Released` too) takes the deadline's policy first, whichever message comes first, and runs no intent it dropped; a call that never returns is abandoned at shutdown, logged, and outlives Run. **Don't open the device while a release is unconfirmed, and don't run what a late acknowledgement's deadline dropped.** `TestAStopThatNeverAnswersLeavesTheReleaseUnconfirmed`, `TestAPausesReleaseThatNeverComesIsUnconfirmed`, `TestEnteringWhileAReleaseIsUnconfirmedSaysSo`, `TestShutdownJoinsWithinItsBound`, `TestADeadlineQueuedBehindItsAcknowledgementChangesNothing`, `TestALateAnswerIsRefusedWhateverTheOrder`.
- **The selection moves on the audible report during playback, never on a hand-off, and at once on a command, a deletion or a skip; it is 0 or an ID in the queue.** **Don't select on Submitted or Prepared, and don't mark an occurrence only when its Cut answers.** → History-rules-player.md
- **An edit after hand-off replaces a successor not yet submitted and cuts a submitted one, one call at a time; an edit that changes no successor makes no call.** A hand-off keeps the entries it passed over as refused, so an edit that starts a new pass and puts nothing between it and the occurrence before it neither cuts nor stops it. **Don't cut what a Prepare can replace, and don't touch the session for an unrelated edit.** `TestAnEditBeforeSubmissionReplacesTheSuccessor`, `TestAnEditAfterSubmissionAsksForACut`, `TestAnUnrelatedEditLeavesTheSessionAlone`.
- **The state × command table in the package doc is `policy`, and every cell is tested.** **Don't decide a transport command outside `policy`, don't answer a play command whose session was heard with what came after, don't let another session's Audible or start decide it, don't let a command that moved the target while a skip released share its session with the command the skip carried, and don't let one that named the entry already pending supersede that command.** → History-rules-player.md
- **An entry refused before any of its content played is skipped with its reason once a pass; a failure after content played is a fault.** A pass runs from a session start or a queue change, and one that refuses every entry stops (`all_unplayable`): repeat on makes one lap. ## Player backend (B470 PR 4b2)

- **`internal/player/playback` implements `engine.Backend` over the decoders and `alsapcm.Sink`, PCM only, and plays only what its `Resolver` hands it.** `playback.New` takes a `Resolver`, which maps an `engine.Reference` to `Content` (an `io.ReaderAt` read through an `io.SectionReader` of its `Size`, and the `Closer` that releases it), and a `Locator`, which gives the bound unit now as a `Unit`: its `Endpoint`, its check after open (`Admit`), and a `Label` that never names the serial. A resolver's `*engine.Unplayable` is passed on as it is, and any other error is `missing_file`. The harness's resolver opens the files it was given; release 5a's will open the library's tracks under its URI confinement. **Don't open a path the engine named, and don't open content a resolver did not hand over.**
- **Content is refused before any of it plays, by its kind, and DSD in every mode.** Content inspection chooses the decoder (`decode.Open`), and each occurrence's first chunk (4,096 frames) is decoded at its open, so content that cannot give a frame is refused, never started. DSD, whatever the session's DSD mode, `off` included, is `dsd_not_in_this_release` (`playback.ReasonDSD`), since no setting turns DSD on yet; `engine.ReasonDSDOff` is for the release that plays DSD. Floating-point PCM and every other decoder refusal keep the decoder's own reason (`float_pcm_refused`, `unknown_container`, `lossy_refused`, `unsupported_bit_depth`, `unsupported_channel_count`, …). Content the resolver cannot open is `missing_file`, no frames `no_audio_frames`, and a rate outside `alsapcm.MinRateHz`..`MaxRateHz` `rate_not_supported`. Content the DAC takes in none of its depth's packings is `transport_not_supported`, found by offering them, each refused open closed unwritten. As a successor, a refusal is reported `Refused` and never `Submitted`. **Don't refuse with any reason but the kind's, play DSD in any mode, or start content whose first chunk did not decode.** `TestPlaybackRefusesBeforeAnyContentPlays`, `TestPlaybackRefusesDSDInEveryMode` and `TestPlaybackSkipsASuccessorRefusedBeforeAnyOfItPlayed` pin it.
- **Samples reach the DAC as the decoder gave them, packed as B470's §1 table says, from what the DAC accepts.** 16 bits are packed as S16_LE. 24 bits are S24_3LE, S24_LE (four bytes, the low 24 significant) or S32_LE (shifted left eight, the low byte zero), offered in that order. 32 bits are S32_LE. The packing a DAC took for a rate and depth is offered first until `Discard`. A successor at the rate and depth of the sink before it takes that sink's packing. Nothing converts a value. **Don't convert a sample, offer a packing outside the table, or keep a packing past `Discard`.** `TestThePackingsAreTheDesignsTable`, `TestPlaybackIsBitExactThroughTheEngine` (every golden of PR 1 in every packing, through the engine's real `Run`, the DAC's bytes unpacked and hashed against the reference tools' hashes), `TestPlaybackPrefersTheDepthsOwnContainer` and `TestPlaybackDiscardForgetsThePackingTheUnitTook` pin it.
- **A successor of the same transport follows in the same sink with nothing between, and one of another transport plays after a drain, a close and a new sink, an honest gap its `Join` names.** The transport is the rate, channels, container and packing. - **One reporter goroutine sends a session's events in order, each stage once, and Audible only when the played content crosses an occurrence's first frame.** A successor is `Prepared`, then `Submitted` once its first frames are in the sink, then `Audible` once the sink's `Position.Played` (content frames the kernel establishes the DAC played, never silence) passes its first frame in that sink. A decoder's end of file and a hand-off report nothing. Several boundaries crossed in one measurement are each reported, in order. The first occurrence's Prepared and Submitted are its Start's answer, and the reporter does not send them. The sink measures nothing while the kernel drains a sink's last hardware buffer, so a boundary in its last 200 ms or so is reported when that drain ends. **Don't report Audible from a decoder or a hand-off, and don't send a session's events from more than one goroutine.** `TestPlaybackReportsEachStageOnceInOrder`, `TestPlaybackReportsAudibleWhenThePlayedContentCrosses` and `TestPlaybackCrossesSeveralShortEntriesInOneMeasurement` pin it.
- **Calls honour their contexts; a compensating Pause uses its own bound, detached from caller cancellation. A session's life ends with its release, and no Start opens beside another session's device.** Start answers once its first frames are in the sink. A Release that comes before its Start leaves a record, and that Start opens nothing, not even the content. One that comes while Start opens ends the session's life: the sink opened then ends with it, closed and never written to, and Start answers an error. A Start while another session still holds the device or opens it is refused (`ErrOverlap`, counted in `Stats.Overlaps`), so an engine that broke the order fails a test rather than meet the kernel's busy refusal of the bridge's own second open. - **A pause is the sink's, its release the sink's own, and a resume after it reopens where the binding resolves now, checked, with the frames the sink kept, or is refused with the session left paused.** The sink pauses by the kernel's PAUSE or by zeros, and after `SessionOptions.PauseRelease` lets the device go, which the reporter reports as `DeviceReleased`. - **Giving up a player's identity resets its UUID, reservation and queue together, with the service stopped.** **A reset gives up for good the identity it removes and any the box ran earlier (one an earlier restore replaced on this box), unless, after this box last ran it, another box took it over from this box, by restoring a snapshot this box made, and has not reset it since, running or powered off. Their values were held only by the floor the reset drops. No snapshot of a given-up identity taken before the reset, on this box or another, may restore its player identity again: remove `player-uuid` and `player-ids.json` from every such snapshot, or delete those snapshots. Any other box that still holds a given-up identity's files (one powered off since a migration, say) must be reset too before it runs again. An identity another box took over from this box by a restore, after this box last ran it, and has not reset since, is not given up: that box's floor holds it, and its snapshots stay valid. Never repair a reservation from a snapshot or delete it while keeping the identity.** → History-rules-player.md
- **Serve's player tests run the real engine on a stand-in backend, and the real backend only on content it refuses before the device; they wait on an event or a journal line until the test's deadline, and hold a stalled start at the engine-config seam.** **Don't let a serve test reach `alsapcm.Open`, read a line the supervisor logs on its own time without waiting for it, or stall a start with a named pipe, which the engine refuses at once.** → History-rules-player.md
- **Faults stay in the player: serve recovers panics in what it owns (its supervisor, the goroutine running `eng.Run`, the resolver, the sink notes), and the engine, the backend and the sink recover those on the goroutines they start (B523); a panic in Run abandons the engine, the backend then releases every session it holds, bounded, and the player keeps its share of the data dir's lock until the process exits.** **Don't log a panic's value (the runtime's own error aside, which carries nothing the player read), a serial or a library path, keep a player running past a panic its supervisor recovered, let go of the lock after a panic in Run, leave a dead engine's sessions without a bounded release attempt, promise its outcome before `releaseAll` reports it, or call the engine on a context Run's end does not end.** → History-rules-player.md
- **A restored identity can hand out IDs and tokens its source handed out (backups carry `player-uuid`, not the reservation), so 5a takes the record's policy before a controller sees one.** **Don't hand an ID or a token to a controller from a restored identity before that policy lands.** → History-rules-player.md
