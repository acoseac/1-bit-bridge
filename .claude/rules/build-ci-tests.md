# Build, CI and test discipline

> **Condensed 2026-10-18.** Each long entry here is one line — its bold title plus its own bolded "Don't…/Never…" sentences — ending `→ History-rules-build-ci-tests.md`: that is `ops/History-rules-build-ci-tests.md`, where the entry sits verbatim with its reasoning, measurements and rejected alternatives. **Still binding.** Edit the line here and its long form there in the same commit; new long-form detail goes to that file, never back into this one.

## Build, CI, and test discipline

- **Every release archive and Docker image carries freshly generated third-party licences from the union of the release builds; missing licences fail the release. Never replace build-derived discovery with the go.mod list or skip the before-hook. Require a licence at each effective module root; include compiled-package ancestry and the pinned Go toolchain notices. Unknown notice suffixes fail; never synthesize module grants. Omit unneeded Tailscale webclient and debugeventbus assets with the release tags in .goreleaser.yaml; keep all builds, deploys and CI tests/vet in step through the repository-wide reviewed-site census in check-build-tags, over every operational file and every non-record Markdown file the walk reaches (records by basename: engineering-log.md, History-*, plan-* and release-notes-*). Scan all fence labels except text, plain, plaintext, txt, output, log, diff, patch, json, jsonc, yaml, yml, toml, ini, xml, html, css, sql, go, golang, swift and mermaid; recognize blockquote/list containers and end fences when their containers end, reject backtick openers with backticks in their info, and strip console/session/terminal prompts before comments. The census is the union of build/install/run/test/vet followed after optional flags by a package pattern regardless of executable spelling, unless the verb is in command position (line start; after ;, &, |, ( or !, a VAR=value assignment, or if, then, else, elif, do, while, until, sudo, exec, command, env, time, nohup, nice), where it is the command itself (coreutils install, the shell's test); the executable rule (a case-insensitive Go path or variable before a verb even without a package; includes go.exe, go1.27.3 and gotip); and the tool list (gotestsum, staticcheck and golangci-lint wherever named, its GitHub action included; dlv debug/test/exec after any flags). Match with quotes, backticks, commas and brackets as separators only on the matching copy. Keep original logical lines and multiplicities; review ambiguous matches. Static analysis cannot see a verb computed at run time, a package argument and a verb on different unjoined lines, or a tool not on the list that drives go. Discover with those same tags; refuse YAML null, boolean and numeric tag spellings. Refuse linked web packages and every non-main-module embed outside the exact module@version/package/file allowlist; exercise the real six-target graph in tests. The supplement registry is empty. Docker generates notices with the full go.mod patch toolchain and copies them into its final stage. Pin embedded-asset supplements to exact module versions and re-audit on upgrades or replacements. Discovery refuses vendor trees, a non-default GOFLAGS or workspace, and non-default architecture feature levels.** (B500) → History-rules-build-ci-tests.md

- **A timeout is not a failure, and the difference is one flag.** A local
  `go test -race` without `-timeout` uses Go's 10-minute default, while
  the Makefile passes `30m` — `internal/admin` reported `FAIL … 600.758s`
  under CPU contention and passes in **826s** with the flag. The signature
  is a duration landing on exactly 600s with a goroutine dump and no
  assertion. Don't report one as a code failure.
- **A package-local test run cannot see a tree-wide guard.** Renaming a
  test in `internal/manifest` left a docblock citing the old name;
  `TestEveryCitedTestNameExists` lives in `cmd/bridge` and caught it on
  CI's macOS leg after a local `go test ./internal/manifest/` had passed.
  After a rename, run the package that holds the sweeps.

- **A test that parks a call in a seam lets it go in its cleanup apart from whatever the parked call holds: the call waits outside the Once that marks it parked, and its release has a Once of its own** (2026-11-09, B728 B9 round 13). In #1434's round 13, `…AnOccurrenceBesideAWriteIsNotRevoked`'s first case parked a write inside a Once (`once.Do(func() { close(in); <-release })`) and its cleanup asked that Once before it closed `release`: a failure while the write was parked left the cleanup on the Once's mutex, which the parked call held waiting for that release, and CI's macOS leg waited out the package's 30 minutes (run 42558744822). That round's `parkedWrite` and round 2's `gate` had the shape, and its `…ACaseEndingWithItsWriteParkedLetsItGo` ended a case with its write parked, as a failure ends it (the three retired with the write beside what plays, B728 B9 PR 2). **Don't ask a parked call's Once, or anything else it holds, before letting it go, and don't take a passing run for proof: only a case that ends while the call is parked runs that cleanup with it parked.**
- **A state the code clears again is looked for while a barrier holds it, or read from what stays** (2026-11-09, B728 B9 round 13). The engine's `Snapshot.Track` names the occurrence heard and is cleared at its session's release, and the reporter can send its Audible and its Finished in one step: with the fake DAC free from before the play, a converted DSD64 track of 0.25 s played out on a loaded runner before the case's first look, which no later change could meet. - **A test that follows a case on a goroutine of its own bounds each phase by that phase's own waits, and the property alone by the bound it pins** (2026-11-09, B728 B9 rounds 14 and 15). #1434's `…ACaseEndingWithItsWriteParkedLetsItGo` timed its case's setup and body as its cleanup's, under one bound of 2W from `t.Run`'s start: a slow but healthy run (2.7W of waits, each within its bound) failed as a cleanup that waits, and its fallback freed the write through the cleanup's own Once and then waited for the case's end unbounded, so a cleanup that never let go hung to the package's timeout. It then timed the body by the body's own exit, a channel the body closes in a call it defers before its setup, which runs before any cleanup, within the body's waits' bounds and one of margin, and classified the case by what it signalled and when, the exit's recorded time against its deadline and a mark the body sets once the cleanup under test is registered, never by which of two ready channels a select took (round 15: the case's end, after every cleanup, stood in for the body's, so a case that failed early and was slow to clean up was reported as an overrun, and a late mark found ready beside the case's end went unreported); a case that ended before its mark kept its skip or its failure with nothing reported, and its cleanups had what was left of the body's bound and the shutdown's; it gave the cleanup one watchdog; past that freed the write through an escape no Once guards (`parkedWrite.abort`); and joined the case within its remaining cleanups' bounds and one of margin, a case that cannot be ended being a panic that names the phase, since `t.FailNow` cannot unblock its goroutine (the case retired with the write beside what plays, B728 B9 PR 2). **Don't time a phase under another's bound, take a case's end for its body's, decide by which ready channel a select took, free a parked call through anything the code under test may hold, or join a case without a bound.**
- **A command a loop repeats takes a context of its own each time, in a func literal whose deferred cancel runs when the command's `Fatal` does** (2026-11-09, B728 B9 round 14): the rig's `insert` gave one watchdog to its whole loop, so n refs, each answered promptly, could cross it together and fail as a deadline with nothing hung. **Don't share one bound across a loop's commands, or cancel a per-iteration context at the iteration's end rather than by defer: a `Fatal` skips it.**
- **A test waits only for what every ordering the code allows gives it, and forces the ordering it judges by a barrier** (2026-11-09, B728 B9 round 16). Two waits hung on CI for an ordering the code may skip. `TestNativePrefillCancelledByItsEndedLifeIsNoFailure` waited for the native watcher's revocation (`lifeEnded`) once the life had ended, where the writer ends the sink on its own: a watcher run late finds the life's end and the writer's both ready, its select takes either, and the one that took the writer's end never ran the hook (Windows at round 14's head, macOS at round 15's: neither dump holds a watcher). #1434's `…AGaplessSuccessorWaitsForAWriteNoLongerThanTheSinksLookahead` waited for the producer to hold b for a write made pending after b's open, with nothing to keep the producer from handing b into a's sink first; and a soak under load (GOMAXPROCS 3 beside 20 busy processes) found a third in the same test, which 200 quiet runs had passed: the drain for b's transport ending between the write's publish and its reconciliation, where b's own sink opens and its activation takes it back unwritten, beside the test's "no sink opened for b". The three tests whose writer ends the sink on its own now run in both orders, the writer held at its end (`nativeSeams.ending`) until the watcher holds, or the watcher held before its select (`watching`, `watched`) until the writer has ended the sink and then let go to take either, each order judged by what it legitimately does; the gapless test held the producer in a (`Seams.ProducerStep`) until the write was pending, and the DAC's time at the floor before the sink's STATUS that shows it (`FakeKernel.ParkStatusAfterPlayed`): the producer's floor is that measurement, which the test synchronized on (the writer back on the DAC), never the fake's clock; and its two endings were cases of their own, the write answered before the drain ends, and the write held where it has published and not reconciled (`Seams.Published`). That case retired with the write beside what plays (B728 B9 PR 2); PR 1's `TestAGaplessSuccessorWaitsForJudgementOnlyAboveTheSinksFloor` keeps its barriers with a policy change for its trigger. Each wait at a forced ordering is bounded by a few seconds (`ordered`, `alsapcm.Ordered`), failing by its name with the goroutines. **Don't wait for a hook on one arm of a select another arm can win, or for a step the code under test can pass before the barrier that should catch it is in place; don't take a grant of the fake's time for the sink's measurement of it, or a passing run, or a quiet soak, for proof; and don't let a wait at a forced ordering reach the watchdog.**
- **A wait at a forced ordering looks for what stays once it holds, and a gate a test makes before its rig is let go before the rig stops** (2026-11-09, B728 B9 round 17). #1434's `…AGaplessSuccessorWaitsForAWriteNoLongerThanTheSinksLookahead` looked for the sink's writer back on the DAC once the floor's measurement was let go: the reporter's step that `tickWithin`'s second send begins can come after it, the producer reading the floor and the sink draining before the look, and `FakeKernel.When` then never meets the writer waiting again (Codex's review of round 16; forced, red at round 16's head). - **A case named for an ordering asserts that its run took it, holding the goroutine whose read decides the order rather than racing the step that wakes it, and a call a case says waits is marked where it begins** (2026-11-09, B728 B9 round 18). #1434's `…AGaplessSuccessorWaitsForAWriteNoLongerThanTheSinksLookahead` had a case for a reporter's step after the floor's measurement that looked for the writer back on the DAC or the drain, so a step `tickWithin`'s second send began late could drain the sink before the case's own step, and the case passed without taking its path (both reviews of round 17): it then held the producer at its wait across the measurement (`producerHold.holdWait`), where a step that comes leaves only a wake, and each case's look asserted the order its case forces. - **A trigger a case's own hold can block completes on whichever comes first, the trigger taken or the hold reached, and says which; a step pinned to a measurement parks that measurement before its time is granted and holds the reader across its release; and an outcome is told by what the device was given, never by a seam every outcome fires** (2026-11-10, B728 B9 round 19). #1434's `…AConvertedJoinWindowWaitsForAWriteThatChangesItsSuccessor` had straddle cases that sent a tick and waited for a reporter to take it while the decision they hold keeps the session's lock, which a reporter's step under way waits for (Codex's review of round 18): its `decide` then took either and logged which. - **A synchronous call a case makes after a step that may leak what the call waits for (a lease, a turn, a slot) is made only once the case has seen that free, through a hook that reads it, so a leak fails the case at once and names what is held** (2026-11-12, B728 B9 PR 2 round 2). `TestAStartIsAdmittedAfterAWriteThatDidNotLand` made its Start and its next write on `context.Background()` after a write that did not land, so a configuration lease or a writes' turn that write leaked would have held either to the package's timeout: a bound on the call (`within`) fails only at the watchdog, a minute on, and the seam that counts the Start's wait (`Seams.Leased`) is read after the Start returns. - **A test that never touches the wiring proves nothing.** Three shapes, all of
  which shipped a dead feature with a green suite: a helper nothing calls, a
  type nothing constructs (a stub implementing the interface directly, while
  production passes a different concrete type), and a handler nothing dispatches
  to. Drive the real entry point — `Handler()`, the real Provider, the real
  endpoint — at least once per feature.
- **A docblock that names a test is a claim, and six of them were false.** → History-rules-build-ci-tests.md
- **A guard that scans SOURCE must parse, or strip comments, when the thing it
  forbids is named in the commentary beside it.** `player_audio.go`'s docblock
  says "Deliberately NOT `dlna.defaultMIMEForExtension`" — a text scan finds that
  and reports the rule as broken, which it did on the first run. Walk the AST, or
  strip; and anchor on an IDENTIFIER, never a string literal, because
  `stripGoComments` blanks literals too.
- **A fixture that omits a live gate describes a different bridge than production.** → History-rules-build-ci-tests.md
- **A stand-in for an older release shows only what it was written to do: what that release does with something the stand-in never reads (an environment variable, a file it does not open) is shown by that release built from its tag's tree (`git archive <sha>`, its own make tags and version stamp), and the record names the runs** (2026-11-09, backlog B761's round 3: the run-as-bridge copy's `predatesUpdateSwitch` reads the settings file and nothing of the environment, so the claim that 0.2.3 ignores `BRIDGE_UPDATE_CHECK_ENABLED` took 0.2.3 itself, its settings check run with the variable off and with a garbage value, beside a variable it binds as the control). **Don't take a stand-in's green for a claim about what it does not model.**
- **Commit BEFORE the negative control.** `git checkout --` and
  `git restore --source=HEAD` revert the whole file, so a control run against an
  uncommitted round silently takes the round with it. This file already recorded
  the lesson; I hit it twice in one session anyway. And a control that fails to
  BUILD reads as "control invalid", never as a pass — revert the test fixture
  alongside the production line so the control compiles.
- **...and once you HAVE committed, `git stash` is a no-op, which is the same trap inverted.** → History-rules-build-ci-tests.md
- **Negative-control every load-bearing assertion**, and check what the mutation
  actually did. B514's filesystem tests use explicit mount tables and stat
  answers; unavailable Linux/Windows runtime checks are reported separately
  from cross-compilation. A real symlink with fixture filesystem identities
  pins upper-target evidence and nested overlay/FUSE lookups through
  `mediumOn`, the function Linux's check calls; its platform reader is stubbed, so it shows
  that `mountIDOf`'s Go wrapper resolves nothing, not statx's no-follow flag. A POSIX mode-0 permission fixture skips Windows
  and root; its ENOENT sibling still runs. → History-rules-build-ci-tests.md.
  A control that fails to BUILD reads as "control invalid", never
  as a pass — and most "just disable this branch" edits delete a variable's only
  use. A control that mutates the *wrong occurrence* is worse, because it
  passes: identical blocks in two tests in one file, or a first-occurrence
  replace, will silently prove nothing.
- **A fixture must be a value the transformation would actually change**, or the
  test pins nothing (an "upstream metadata always wins" test used a name that
  cleans to itself and passed against code that overwrote unconditionally).
- **Pin cross-repo and cross-cycle contracts with CAPTURED bytes**, never a
  second hand-written copy of the offsets — two copies can be wrong together,
  and were.
- **Assert omitempty absence by unmarshalling and checking key-absence**, never
  a substring probe on the raw body.
- **`hidden === false` says nothing about an ancestor.** UI assertions from JS
  can and did lie; seed a throwaway bridge and drive the console in a browser
  before believing a green suite about UI. `document.visibilityState` is
  `"hidden"` in an automated tab, so `loading="lazy"` images never load and any
  perceived-performance claim measured that way is suspect.
- **A node harness that `withReachedFunctions` assembles carries a function
  called only inside another call's parentheses (`stageFiles(collectFromInput(…))`)
  only when the harness names it as an entry: the call scan consumes the
  character before a name, so it misses the inner call, and node answers the
  first event that reaches it with a ReferenceError, at the defect and at the
  fix alike** (2026-11-08, backlog B797). `requireCarried` checks an assembled
  script before node is looked for (a top-level binding of app.js its functions
  read that the harness does not declare, a name it calls that it neither
  declares nor has as a global), so a host without node catches it. **Don't
  take a node test that skips for one whose script would run.**
