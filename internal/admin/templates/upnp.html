UPnP upstream servers

Upstream UPnP/DLNA MediaServers (e.g. a Chord 2Go's microSD cards) whose tracks the bridge ingests into its manifest and proxies to iOS bit-exact. Configure them here, then iOS sees them as normal bridge content.

Not available on public deployments

This bridge is running in public mode (TLS via Let's Encrypt, advertised on a public hostname). The upstream-UPnP feature is structurally incompatible with that posture and bridge.yaml validation rejects the enable bit:

  • SSDP is LAN-only. The bridge would never discover an upstream MediaServer over a public network — multicast doesn't traverse the public internet.
  • Upstream byte URLs are RFC1918. Even if you pasted a manual description URL, the upstream's /MediaItems/<id> byte URLs reference the upstream's private LAN address — unreachable from the public VPS the bridge runs on.

To use upstream UPnP servers, run the bridge in loopback mode on the same LAN as the upstream (the canonical home-deployment shape).

Feature disabled

The upstream-UPnP feature is off. Enable it in bridge.yaml: 

upnpUpstream:
    enabled: true

Then restart the bridge and return to this page.

Configured

Servers the bridge actively ingests + proxies. Click Rescan to force-walk one now (e.g. after adding new music to the upstream), Edit to change the friendly name or path prefix, or Remove to drop it from the config.

Discovered on LAN

MediaServers the bridge has seen via SSDP but isn't yet configured to ingest. Click Configure… to add one — the UDN + friendly name pre-fill in the add form.

Add manually

For servers SSDP didn't surface (e.g. multicast-blocked routers, separate subnets). Paste the upstream's /rootDesc.xml URL instead of its UDN; the bridge resolves the rest at scan time.
