General

Shown in the iOS pairing UI and mDNS TXT records.
How often the full walk runs. Defaults to 21600 (6 h).
Adds an fsnotify-based watcher so newly-dropped files appear within seconds instead of waiting for the next periodic scan (which stays on as the safety net either way). Off by default — best for local-disk libraries; NAS mounts on a flaky network can thrash incremental scans. The watcher starts at bridge serve startup, so a change takes effect after a restart.
Set at bridge init time; not editable here.

Enrichment

The background enricher fills in cover art + MusicBrainz IDs. Choose where it looks: the public MusicBrainz + Cover Art Archive services, or a self-hosted Atlas mirror on your own network.

The Atlas host serves both MusicBrainz lookups and cover art; the bridge derives the right paths automatically.
Advanced: raw mirror URLs
Accepts artist bios + album descriptions pushed by the 1-bit app (which holds the Atlas access key — the bridge never sees it) and serves them back to all your devices via /v1/atlas-meta. Off by default.

Acoustic fingerprinting

Identifies tracks whose tags no text match can fix by fingerprinting the audio (fpcalc → AcoustID), then hands the recovered names back to the enricher above. Needs fpcalc (Chromaprint) installed on the bridge host and a free AcoustID application key — the lookup goes to AcoustID's own matching service; a self-hosted Atlas mirror holds no fingerprints and can't answer it.

Registered free at acoustid.org/new-application. Stored in bridge.yaml; the ACOUSTID_API_KEY environment variable, when set, wins over the stored value. Leaving the field blank keeps the current key.

Networking

Updates

The bridge polls the GitHub Releases API for new versions. Operator-triggered install is always available on the dashboard; auto-install is opt-in.

When enabled, every successful poll that surfaces an update triggers download → verify → atomic swap → restart, subject to the same active-stream gate as the manual Install button. Default off — opt-in is recommended even on stable channels.
Restricts auto-install to a daily window in server-local time. Leave empty to permit any time. Wraps midnight (e.g. 23:00-06:00) for overnight schedules.
How often to poll the GitHub Releases API. Defaults to 6 (4 polls/day, well under the 60/hr unauthenticated rate limit). Lower values are clamped to a 1 h floor at runtime.

Audio quality

Offline PCM upscaling renders high-rate FLAC sidecars from CD-rate sources via sox(1). Disabled by default — opt in below, then run bridge upscale on the server to populate the cache (or trigger from the iOS app's "Generate upscaled version" context menu).

When enabled, the bridge runs a long-lived sox worker pool inside bridge serve, advertises upscaleEnabled: true on /v1/health, and accepts POST /v1/upscale requests from iOS. Cached sidecars survive across toggles — disable to hide variants from clients without losing converted files. {{if .Data.UpscaleSoxMissing}}

Generates 16-bit family-preserving downsamples (44.1 / 48 kHz) from hi-res PCM so CarPlay / cellular streams start fast. On by default; only active while PCM upscaling (above) is enabled — the optimize pipeline shares its sox worker pool. Advertised to iOS on /v1/health; wired at startup, so a change takes effect after a restart.
Builds the optimized variants above ahead of time instead of waiting for a device to ask. Without this, the first time you play any track in the car the app streams the full hi-res file — the optimized copy only exists in time for the next play, so on shuffle the saving rarely lands. Off by default: it spends disk and CPU on tracks nobody has requested yet.
Sweeps newest-indexed tracks first, at most {{.Data.AutoOptimizeMaxPerSweep}} per pass, and stops if free space on the variants volume would fall below {{bytesHuman .Data.AutoOptimizeMinFreeBytes}}. Runs on the low-priority lane, so an on-demand request always jumps the queue. Applies immediately — no restart.
