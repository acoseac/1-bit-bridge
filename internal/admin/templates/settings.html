Updates

The bridge polls the GitHub Releases API for new versions. Operator-triggered install is always available on the dashboard; auto-install is opt-in.

When enabled, every successful poll that surfaces an update triggers download → verify → atomic swap → restart, subject to the same active-stream gate as the manual Install button. Default off — opt-in is recommended even on stable channels.
Restricts auto-install to a daily window in server-local time. Leave empty to permit any time. Wraps midnight (e.g. 23:00-06:00) for overnight schedules.
How often to poll the GitHub Releases API. Defaults to 6 (4 polls/day, well under the 60/hr unauthenticated rate limit). Lower values are clamped to a 1 h floor at runtime.

Audio quality

Offline PCM upscaling renders high-rate FLAC sidecars from CD-rate sources via sox(1). Disabled by default — opt in below, then run bridge upscale on the server to populate the cache (or trigger from the iOS app's "Generate upscaled version" context menu).

When enabled, the bridge runs a long-lived sox worker pool inside bridge serve, advertises upscaleEnabled: true on /v1/health, and accepts POST /v1/upscale requests from iOS. Cached sidecars survive across toggles — disable to hide variants from clients without losing converted files. {{if .Data.UpscaleSoxMissing}}

Clear all upscaled variants?

This deletes every cached .flac sidecar in {{.Data.UpscaleStoragePath}} AND the matching rows in track_variants. Paired iOS clients will reconcile via the upscale.deleted SSE event and drop their cached variant references.

The action is not undoable. Source files are untouched — operators can re-upscale anything from the Library inspector or from the iOS app's per-track menu after this clears.
