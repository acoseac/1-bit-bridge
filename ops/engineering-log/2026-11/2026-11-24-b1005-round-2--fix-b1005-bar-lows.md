### The changes

Production: 82 lines added and 13 removed (53 of the added code, 29 comment). Item by item, the
explicit Pause's cancel took 54 added lines (39 code, 15 comment), the most of any.

- **An explicit Pause lets go of a start the gate holds.** A row clicked, or a Play that took a
  failed track's skip, waits for the epoch or behind its barrier; the lock screen's Pause cleared
  the intent, which only a continuation asks, so the barrier's answer ran the reader's start and
  played the row. The lock screen's Pause (`pauseNow`) and the bar's Pause (`toggle`'s pause) now
  call output.js's `cancelStarts`, wired beside the start gate (`setStartGate(gate, cancel)`): a
  start waiting for the epoch is dropped and sends no barrier, which would pause the bridge's
  engine, and one behind the barrier in flight runs nothing on its answer unless a start asked
  since takes its place, the barrier then ending quietly (this browser's phase, the unconfirmed
  line a lost answer left gone, no line of a start). The element's pause event, which the
  browser's own pause fires too, cancels nothing, so a Play made before that event, and a row
  waiting while the browser pauses the old track, still play; a cancelled slot is taken by any
  start asked after it, the browser's own play included.
- **A paused handover stops spinning, and a reader's Play supersedes its deferred play.** A
  positioned handover loads stopped and shows starting until its metadata; the lock screen's Pause
  there left the spinner on, the element being paused already and firing no pause event. It now
  shows the bar stopped at once. A start asked over a paused element now clears what this browser
  meant to play there (`requestStart`), so a handover's deferred play only seeks and the reader's
  Play plays once when the gate admits it, where the metadata coming first played the element
  twice; and `requestStart` hands the gate a drop (`startDropped`), so a reader's start the gate
  refuses shows that element stopped and not starting.
- **A track that plays to its end breaks the failure streak.** The skips past unplayable tracks
  counted on through the good tracks between them, so an album of bad and good tracks in turn
  stopped on its fifth, and under repeat one a replay's failure after two others said the stop.
  The count restarts at a track's end; a play event, which comes before a source's error, still
  breaks nothing.
- **After an abort the button does what it shows.** A fetch the user aborted (code 1) fires no
  pause, so the bar showed Pause while the button asked the gate for a start. Code 1 is no failure
  in `toggle`: the Pause shown pauses, asking the gate nothing, and once stopped the Play shown
  starts through the gate, as Play over any stopped element does.
