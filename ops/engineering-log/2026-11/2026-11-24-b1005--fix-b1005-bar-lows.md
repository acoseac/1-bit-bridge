## 2026-11-24 — B1005: the player bar's follow-ups to B634 PR 2

### What

B634 PR 2 (#1561, `80e6d288`) left follow-ups, each pinned by line at its merge. This change takes
the ones that hold, in the bar's browser half (`audio.js`, `output.js`, `nowplaying.js`,
`player.css`), its harness and cases, the source tests, and the rules line with its long form. No
server change, route, protocol field or server state, and no change to the gate's design.

### The changes

Production: 81 lines added and 31 removed (54 of the added code, 27 comment).

- **A resume's wait the reader cancels ends its spinner.** `readerAction` let go of a resume of
  the browser's own that waited on its barrier and left `loading` set, so a row clicked beside a
  bridge that plays left Play spinning. It now clears the spinner with the wait and publishes
  nothing; each caller's own emit says so, and `playQueue` and `advance`, which had none on a
  refused start, emit. `toggle` drops the clear it duplicated.
- **Only the playing row's removal counts.** `removeAt` counted every removal as the reader's
  action, so removing a row that is not playing cancelled a resume nobody stopped. It counts in
  the playing row's branch alone. An append, a seek, the level, shuffle and repeat stay
  uncounted: none changes what a waiting resume plays. Removing the playing row with no playable
  track after it left `state.index` where it was, an empty queue pointing at a track and the
  removed one still sounding; the queue now points at no track (-1) and the element lets its
  source go.
- **One start a playback after a switch back.** A positioned handover loads stopped and plays at
  its metadata. The reader's Play before the metadata played the element, and the metadata then
  started it again on the older permit, which, refused, showed the bar stopped while the browser
  played. The deferred play now runs only while this browser means to play and the element is
  paused, so a Pause since cancels it too, whatever its permit.
- **An album skips a track the browser cannot decode or fetch.** A browser raises the source's
  error before its metadata, the bar's play still pending, and refuses that play with
  NotSupportedError. `playRefused` ended the intent on it, and the skip's timer asked `playing`,
  which a source refused before any play event never showed, so the album stopped there, said
  nothing more, and a playing positioned handover whose source failed before its metadata never
  skipped. The refusal is now the error's: the bar shows the track stopped, the timer asks the
  intent and the generation, the skip moves on under repeat one too (`advanceNow`'s `skip`, where
  repeat one replayed the failed element, which a browser refuses at once), and the stop after
  three in a row ends the intent. A handover taken stopped still never starts.
- **Play over a failed track starts again.** A failed element is not paused, so `toggle` paused
  it. Play over one is now a start through the gate that decides when it runs: a source the
  browser cannot use moves to the next playable track, taking the skip's place behind its
  barrier, and stops at the end with repeat off; a network or decode error reloads the track, its
  automatic retry there again. The lock screen's Pause called `toggle` too; it is now a pause of
  its own (`pauseNow`), so it never starts a track.
- **A failure past its retry ends the intent.** The retry's barrier could answer after the second
  failure and play the failed element under "Playback failed".
- **A handover's selected entry with no track.** `handoverOf` left the index at -1, and `take`
  then played the first entry at the gone entry's position. The next kept entry is selected, from
  its start; with none after it the queue is taken stopped at its first kept entry.
- **The output menu.** It closed only on Escape and on a click outside, so Tab past its last pick
  left it open. The focus leaving it now closes it, for the Output button too; the button's press
  keeps the focus (its `mousedown` prevented while the menu is open), so its click closes the menu
  once with no close and reopen, and the menu takes the focus itself (`tabindex="-1"`) so a click
  on its words keeps it. The chosen pick carries a check (`::after`), which the focus ring, alike
  to the chosen border, lacks. The Output button no longer claims a popup: the menu is a group of
  buttons.

### Tests and records

- The harness's element settles the promises of the tasks a load removes, a play's resolved and
  those a pause took refused with AbortError, as the load algorithm does
  (`TestTheHarnessElementSettlesWhatALoadDrops`). Its pending-play mode drives the browser's own
  order in the skip's cases. A case reaches `continueStart`'s unwired branch
  (`TestAnUnwiredGateLetsNoTrackGoOnByItself`).
- Every node lookup of the player output's tests is `barNode`'s, which fails under CI and skips
  elsewhere, and `TestEveryNodeLookupOfTheOutputsTestsIsBarNode` finds each `exec.LookPath` by the
  files' syntax: the stream test and the Player page's had skipped under CI.
- The replaced-queue case passed through the latch, so only a source pin held a continuation's look
  at the generation; `TestAContinuationBehindABarrierLeavesATakenQueueAlone` hands the browser a
  queue while a skip waits, and its doc and the replaced-queue case's say which pins what.
- The late answer's body is counted unread; the record-confirmation case asks that nothing is left
  pending; the lock screen's handlers are asserted set before they are called.
- `TestEveryStartOfThisBrowserAsksTheGate` follows a start output.js alone calls (`start`, `take`,
  `resume`), so an exported `replay() { start(); }` fails it, and reads what is handed to a gate
  (`requestStart`, `continueStart`) and a load made stopped as no play, so `removeAt` passes by
  what it does, no longer by its name.
- The control's `readBackEnded` reads its premise before each record, so a record that ended beside
  a hook's failure is never taken for the case's outcome.
- `TestFailureAutoAdvanceIsGuarded` pins the intent in the skip's condition, comments stripped.
- Records: the long form's mark sentence now says what the code does (a `play` event takes the
  oldest live mark, so a browser's own play queued before a marked call takes that call's mark,
  the call's own event is then paused and asked of the gate, and nothing unasked sounds; matching
  an event to its call would take a model of the element's task queue), with
  `TestTheOldestMarkGoesToTheFirstPlayEventAndNothingUnaskedSounds`; it names the calls that cancel
  a waiting resume and those that do not; the read back's throttle is one stamp for the whole bar
  by design; the Don't on stream records reads "a switch, or an edit but a delete". The round-2
  entry of B634 PR 2 is corrected where it claimed more than it showed.
- `TestTheChosenPickCarriesAMarkTheFocusRingLacks` pins the check at the source.

### Not in this change

- A continuation refused beside a silent bridge: the bar sets its line only beside a bridge that
  sounds, and a permit refuses only for a newer pick, another output, or a newer state that sounds
  now, so the sequence described goes on playing. No line was added.
- The DAC opened, then let go about 28 ms later, on a switch to the bridge at a position: no probe
  opens it. It is the first session of a replace that plays, which the replace's follow-up seek
  ends (a seek is a session of its own) before the session at the position opens. Starting that
  session at the position is server work, an item of its own.
