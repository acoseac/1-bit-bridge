> The long forms of `.claude/rules/openhome.md`'s entries, written with it on 2026-10-23 (B470 PR 5a2a). **These entries are still binding.** The rules file keeps each as one line ending `→ History-rules-openhome.md`; change an entry here and its line there in the same commit. Each `##` names the section the entries are in. The record, with the red-first runs and the negative controls, is `ops/engineering-log.md`, 2026-10-23, B470 PR 5a2a.

## The player's OpenHome surface (B470 PR 5a2a)

- **`output.player.openhome` is the opt-in, off by default, and it stays off by default until PR 5a4.** Why off: 1-bit finds a Source by SSDP and, for a host advertising one, never probes for MPD (the iOS research note on 7b66325d, MPDP:5-9, 151), so publishing a Source that answers every action 602 removes that host's MPD row, the one way to cast there today; and with 602 for every action a cast start aborts on its required source read (`SourceIndex`) with the previous output kept, so the surface has nothing to offer a controller before 5a3 and 5a4. It is read once, from the boot snapshot (`planServePlayer`, with the player's other gates): a change applies when serve next starts, as the player's own block does. The surface starts inside the player's supervisor once the engine runs (`bridgePlayer.start`, `startOpenHome`), so a player that does not start (any gate, the engine refusing its storage) starts none of it: no socket, no goroutine. With the opt-in on and the player simply off (`enabled: false`), `planServePlayer` returns `openhomeOff` and `startServePlayer` logs "player: the OpenHome surface does not start" once; a player refused for another reason already says why (Validate's line, or "player: not started"), and the surface adds nothing to it. The port: `openhomePort`, nil for `DefaultOpenHomePort` (7792: nothing in the repo named it, and it follows 7788 to 7791), 0 for a port the kernel picks per address (config-lifecycle.md's ports admit 0), every URL then carrying the port the request arrived on. It is validated as its neighbours are: the block's strict reader takes the two keys (a word or a list leaves the block unread, naming the key and its line), and `Problem` refuses a number outside 0 to 65535, either turning the player off with a reason that quotes no value (config-lifecycle.md's rule on values; `TestNoLoadRefusalOrWarningCarriesAValue` covers the key through envBindings). Both keys take an environment override as every scalar of the block does (`BRIDGE_OUTPUT_PLAYER_OPENHOME`, `BRIDGE_OUTPUT_PLAYER_OPENHOME_PORT`, from `envBindings`'s walk; `TestThePlayerIsEnvSettableButItsSerialIsNot`), applied at Load, so they are the boot snapshot's too, and a value the variable does not read as is ignored with a warning naming the variable alone. A fraction reads as its whole part, as every whole-number line of the block does: yaml.v3 truncates a float into an int (a follow-up). With the surface on, `PlayerEnabled` refuses a port another listener of serve binds (`openHomePortClash`): `listenAddress`'s (the API, TCP and HTTP/3's UDP), `adminAddress`'s, `dlna.listenAddress`'s whether or not DLNA is on (it can be turned on and the surface would then lose the race for the port), and `output.loopbackPort`'s (bound once `output.mpd` resolves on, which can happen at any time after boot through `OnActive`); an empty address is its default (applyDefaults fills them, a Config built in memory may not); 0 clashes with nothing. It is a refusal of the player, as the block's other refusals are, and Validate logs it once each time the reason changes (`logPlayerOff`); it does not clash when the surface is off, since the port is then never bound. Rejected: refusing the surface alone, which would need a once-logger of its own and a second predicate beside `PlayerEnabled` for one value of the block; and refusing the clash whatever the opt-in, which would turn a player off over a port it never binds. `--addr` at serve time can still move the API onto the port: the surface's bind then fails, that address alone, and says so.

- **The surface is a listener of its own: one IPv4 socket per address `lan.Look` serves, never a wildcard and never on DLNA's listener, keyed by `lan.Address`, followed by a listing every 5 s.** DLNA's guards do not meet the player's rule: `servedOnlyListener` closes a connection whose local address is not served, and serves every LAN address to any source; `ownHostOnly` passes an empty Host, `localhost`, loopback literals, every advertised host and any address of this host, with any port. The player's rule is per connection (a source on the arrival address's link) and per request (the exact address and port), so it has a listener of its own, which DLNA's being off (its default) does not change. Each eligible IPv4 address of each eligible interface (`internal/player/lan`: up, running, multicast, not point-to-point, no Tailscale address, RFC 1918 or 169.254) gets its socket on the configured port; `lan.Look` lists the served addresses with their on-link prefixes and their interfaces' names and indexes, and every address the box holds, from one listing. The socket's key is the whole `lan.Address`: the brief asked for the address and its prefix, and the interface's index is in it too because the restriction (the next bullet but one) names the index, so a socket bound to an interface that was made again under another index would hear nothing. A listing every `Limits.Rescan` (5 s, and `Rescan` for a test or a later netlink trigger) updates the admission snapshot first, then closes each socket whose key is no longer listed (and the connections its server holds), then binds each new one; a listing that fails keeps what is bound and is said once a streak, since one failed listing must not take the surface off the LAN (servedAddrs keeps its snapshot for the same reason). A bind that fails (the port taken, the address gone between the listing and the bind) fails that address alone: it is in `Status.Failed`, said once until it binds or its error changes, and tried at the next listing; the player, the library and the rest of serve never see it. The surface closes a retired socket's listener itself as well as by its server's `Close`: `http.Server.Close` closes only the listeners `Serve` has begun to track, so a socket retired before its `Serve` goroutine first ran stayed open until that goroutine ran and found the server closed (found by `TestTheSurfaceBindsEachServedAddressAndFollowsThem`, one run in a few; no seam reaches that window, so no control). A container on a Docker bridge is on a link the box serves when that bridge is eligible, as DLNA's residual says.

- **Admission is at accept, before any cap counts.** `admitting.Accept` asks the gate of each connection, in order: its local address is its socket's, while the listing serves that address (`destination_not_served`, which is also what a connection taken in the moment between a listing that dropped the address and the socket's close gets); its source is IPv4 (`source_not_ipv4`), not loopback (`source_loopback`), none of the box's own addresses (`source_own_address`: every interface's, eligible or not, from the same listing, since a connection from one of them is the box's own or a forgery), inside the on-link prefix of the address it arrived on (`source_outside_prefix`: not another address's, a secondary's included, nor another interface's), and of the LAN's classes (`source_not_lan`, `lan.IsLANAddress`: RFC 1918 and 169.254, so a mask a box was given by mistake, wider than its address's class, admits no public address; `TestAdmissionRefusesAtAcceptAndCountsNothing` serves 192.168.9.1/8 and refuses 192.169.0.5). Then the caps. A refused connection is closed at once with a linger of 0, so the peer gets a reset, unread and unanswered, and counts against no cap: a flood of refused connections cannot take an approved source's place. A refusal is logged once per kind and source, 32 at most, since a peer chooses its source. Then, at the request, row 1's second half: the Host must be exactly the address and port the request arrived on (`netip.AddrPort.String`), no default port elided, no name, no mapped or zero-padded spelling, no empty Host, or it is 400, before routing (a foreign Host on a path that is no route is 400, not 404). That is DNS rebinding's answer: a page re-pointing its own name at the box sends that name. Rejected: admitting a source by any served address's prefix (a secondary address's link reaching the primary's socket), and a source check inside a handler, which would have counted the connection and read its request first.

- **The arrival interface is restricted where an unprivileged option exists.** IPv4 on Linux is the weak host model: an address bound on one interface takes a packet that arrives on another. A TCP handshake from outside the prefix needs a route back to its source, so a source in the prefix and a served destination refuse what they must in the ordinary case; the restriction is defence beside them. Linux: `SO_BINDTOIFINDEX`, set in the `ListenConfig`'s Control before the bind; an unprivileged process may set it, or `SO_BINDTODEVICE`, on a socket not bound to a device yet since Linux 5.7 (c427bfec18f2, "net: core: enable SO_BINDTODEVICE for non-root users"; before, both need CAP_NET_RAW), and a listening socket bound to a device is handed only a SYN that arrived on it (socket(7): "only packets received from that particular interface are processed by the socket"). Where the kernel refuses, the socket listens unrestricted and its restriction reads "none: the kernel refused SO_BINDTOIFINDEX (…)", never a failed bind: the prefix check holds either way. Not measured from this session: no Linux host was reached. macOS: `IP_BOUND_IF`, which an unprivileged process may set; measured on the dev Mac (darwin 27, 2026-10-23) with a throwaway probe: a loopback listener bound to en0, dialled on loopback, timed out (its SYN-ACK went out en0), and a listener on en0's address bound to en0 took this host's own connection, which arrives on lo0; so it scopes what the socket sends, and does not refuse a segment by the interface it arrived on (XNU's `inp_restricted_recv` filters by the bound interface only on interfaces marked restricted-receive). Elsewhere (Windows): nothing; `IP_UNICAST_IF` scopes sends, and the player runs on Linux alone. An index of 0 is left unrestricted and says so, since 0 means "no device" to these options. The residual: a router on the LAN that rewrites sources into the prefix (SNAT) is admitted, and so is anything on the link that holds an address in the prefix.

- **The limits.** `DefaultLimits`: 32 connections open and 8 from one source, counted once a connection is admitted (URLSession's default per host is 4 on iOS and 6 on macOS, by Apple's documentation, and 1-bit polls about once a second); 8 slots; a header read deadline (`ReadHeaderTimeout`, 5 s); the whole request's (`ReadTimeout`, 10 s); a control body's own, 5 s, set with `ResponseController.SetReadDeadline` once rows 2 to 5 have passed, so a body that trickles meets it where the whole request's would wait twice as long (`TestATrickledBodyMeetsItsDeadlineHoldingNoSlot` waits 5 s for the 408); a write deadline (`WriteTimeout`, 10 s from when the request's headers were read, which net/http sets per request, so a client that pipelines requests and reads none of the answers holds a write until it, and nothing else ends that write: no read deadline runs while a response is written, `TestAClientThatStopsReadingIsCutOffByTheWriteDeadline` with 4 KiB socket buffers); an idle deadline (`IdleTimeout`, 30 s; net/http takes `ReadTimeout` for an idle connection when none is set, which the test's 5 s wait tells apart); 16 KiB of headers read (`MaxHeaderBytes` 12 KiB and net/http's 4 KiB of bufio lookahead, as `dlnaMaxHeaderBytes` is derived), 431 past it; the body bound, 256 KiB (row 6). A slot is taken once a request's body is read, never before, so a client that trickles holds no slot, and past the slots a request is 503 at once, never queued. The descriptions take a slot too (they have no body). The server's `ErrorLog` is `handshakelog.ErrorLog()`, so net/http's own lines keep no client address (cli-serve.md's rule for serve's servers).

- **The stop.** `Surface.Stop`, once: `stopping` is set, so every request from then on is 503 with its connection closed (`Seams.Stopping` runs there); the listing loop is cancelled and joined within `Limits.Join` (abandoned and counted past it, and a socket it binds after the stop is closed at once); each listener is closed (`Shutdown` closes only what `Serve` tracks), then each server shut down at once within `Limits.ShutdownGrace` (2 s), which closes idle connections and waits for the requests under way; a server whose grace ran out has its connections closed (`Seams.Forcing` runs first); then the Serve goroutines and the handlers are joined within `Limits.Join` (1 s), one deadline for both, what is still running counted in `StopReport.Abandoned` and said. A handler held past its connection's close (a test's seam; production's return at once) is the one thing that can outlive the stop, and the report says so. The join covers the Serve goroutines and the handlers, not net/http's goroutine per connection, so a request that goroutine read just before the stop closed its connection can still reach the handler after the join: it is refused 503 like every request after the stop, with the EXT header every reply carries, onto a connection already closed (`TestARequestAfterTheStopsJoinIsRefusedLikeEveryReply`; red first, it had no EXT header, written only after the handler's count was entered). `StopBound` is the sum, 4 s with the defaults, which serve's player adds to its stop's outer bound. Serve's player stops the surface first in its shutdown (`bridgePlayer.shutdown`, `stopOpenHome`), then the engine, then the backend, so no request reaches the engine as it stops; `TestServeRunsTheOpenHomeSurfaceOnlyWithItsOptInAndThePlayer` reads that order off the journal.

- **A panic in the surface's listing stays in the surface.** The listing loop is the surface's one goroutine of its own beside net/http's, which recovers a handler's panic per request; a panic in the address source (production's is `lan.Look` over the host's interfaces, a test's anything) or in the listing would otherwise end the process, the library with it, which "faults stay in the player" (player.md's 4b3 bullet) forbids. The loop's deferred recover logs at Error with the stack, and with the value only when it is a `runtime.Error`, as `logPlayerPanic` does (a value code panics with could quote what the listing read: the test panics with a path and checks the line for it), publishes so a watcher of `Changed` wakes, and returns: the surface serves the addresses it has bound, follows the interfaces no more until serve next starts, and stops as before (the loop's done channel is closed by the defer registered before the recover's, which runs after it, so Stop's join sees the loop gone once the line is written). Red first: the panic crashed the test binary. The engine's own goroutines are the known limit 4b3 left (backlog B523).

- **Only `/openhome/` is served.** Routes are exact (no `ServeMux`, so no redirect for an unclean path): `description.xml`, and `scpd.xml`, `control` and `event` under `/openhome/<service>/` for the four services' paths (`product`, `playlist`, `info`, `time`); any other path is 404, the admin's, `/v1`'s, DLNA's and media's included, and no reply carries a CORS header. The descriptions answer GET and HEAD, 405 to anything else. The device description is built per request from the address and port the request arrived on (`arrivedOn`, `http.LocalAddrContextKey`), not from Host, so every URL in it is absolute and on the address a controller found, on any of the box's LANs and on a port the kernel picked. Its fields: deviceType `urn:av-openhome-org:device:Source:1`, UDN `uuid:` and the player's UUID (`config.EnsurePlayerUUID`, never the MediaServer's `deriveDLNAUDN`), manufacturer `1-bit`, manufacturerURL `https://1-bit.app`, modelName `1-bit Bridge Player` (which 1-bit never reads), modelNumber `version.ServerVersion`, modelDescription `The 1-bit bridge's own player`, no serialNumber (1-bit hides a DLNA twin by manufacturer and serial on the same host), and the four services, each with its type, its ID (`urn:av-openhome-org:serviceId:<name>`) and its three URLs. modelDescription and the vendor fields are neither of upmpdcli's strings (manufacturer "JF Light Industries", modelDescription "UPnP front-end to MPD"), which 1-bit does not offer, and the research note says "1-bit" matches none of the iOS renderer profiles; their own substrings (RPR:453-484) were not read from this session (an owner check). No Volume service: the player's output is fixed, and 1-bit draws no volume section without one.

- **The friendlyName.** `FriendlyName(room)`: invalid UTF-8 bytes dropped, then every rune outside XML 1.0's Char production (controls other than tab, newline and carriage return, U+FFFE, U+FFFF), then the first 64 runes kept, so a cut never splits a rune; a room that keeps nothing is `1-bit Bridge Player`; the description then escapes it (`xml.EscapeText`). It holds whatever reaches it: config's validation of `room` (UTF-8, no control character, 64 characters) is unchanged, and the builder does not trust it. A room equal to another renderer's name on the same host less "-UPnP/AV" would pair the Source with that renderer in 1-bit; that is the owner's to avoid, and nothing here can see the other renderer.

- **The four SCPDs are the bridge's own tables.** `services.go` holds each service's actions (each with its arguments in order, their directions and their related state variables) and state variables (each with its type, allowed values and eventing), written from OpenHome's action tables, and `service.scpd` generates the description. OpenHome's own files, ohNetGenerated at 22feef5262ed28432783c9bf16bdeb31d4c8bb18 (`OpenHome/Net/Service/Upnp/OpenHome/`, MIT), are test data with their `License.txt` and a README (`testdata/upstream`); no file of theirs is embedded or built in, so no third-party notice ships (the release has no notices mechanism, backlog B500). `TestOurSCPDsAreUpstreamsInventory` reads both as a controller reads an SCPD and compares them exactly, so a table that drifts from OpenHome's fails; `TestTheUpstreamFilesAreTheirPinnedBytes` holds the copies to their SHA-256s (two are CRLF, and `.gitattributes` keeps them unconverted). The SCPDs keep OpenHome's `sendEvents` though GENA is refused: they describe the service as OpenHome defines it.

- **The SOAP layer.** The table is `soap.go`'s and the rules file's, in its order: row 1, admission and the Host; row 2, POST (405 with `Allow: POST`); row 3, no `Origin` header at all, empty and `null` included (403), before the body is read, since no controller sends one and a browser always does; row 4, one `Content-Type`, `text/xml` with a charset of utf-8 in any case, quoted or not, or none (`mime.ParseMediaType`; 415); row 5, one `SOAPAction`, quoted or not, a single `#` between this URL's service type and one of its actions (fault 401, a missing one included); row 6, the body through `http.MaxBytesReader` at 256 KiB (413), read to EOF under its own deadline (408 at it, 400 for another read failure); then a slot (503 at once); row 7, the XML through `encoding/xml` in strict mode with no charset reader (so a declared encoding other than UTF-8 and bytes that are not UTF-8 are 400): no directive (DOCTYPE, ENTITY), the declaration first or not at all, other processing instructions ignored and at most 4, at most 128 elements and 8 deep, at most 64 KiB and 8 KiB per in-argument of decoded text (Insert's 88 KiB holds the engine's 64 KiB of metadata, escaped or not, beside its URI), and nothing after the envelope but white space (400 for each); row 8, one Envelope in SOAP 1.1's namespace whatever its prefix, an optional Header first (at most 8 entries and 8 KiB, 400 past them, as row 7's bounds are; the brief left their outcome open), its entries ignored unless one carries `mustUnderstand="1"` in SOAP's namespace or none (the `MustUnderstand` fault: no header is understood here), then one Body holding exactly one action element whose local name and namespace are SOAPAction's (fault 401 for any other shape); row 9, the action's in-arguments in the SCPD's order, each with no namespace or the action's own (children of a default-namespace action inherit it), none missing, repeated, unknown or nested, each parsing as its state variable's type: `ui4` and `i4` decimal and in range (`strconv.ParseUint` and `ParseInt`: no sign on ui4, an optional one on i4), `boolean` 0, 1, true, false, yes or no in any case, `bin.base64` strictly (`base64.StdEncoding.Strict()`, which ignores line breaks, so they are refused first), `string` any text within row 7's bound; for every action, those with no argument included (fault 402). Nothing is trimmed. Every request that passes is fault 602: no action is implemented, since no controller may read an ID or a token before the restored identity's policy (5a0), and nothing is read from the engine or done to it. Faults: HTTP 500, `text/xml; charset="utf-8"`, `s:Client`, `UPnPError`, the code and its description (UPnP Device Architecture 1.1, §3.2.2: 401 Invalid Action, 402 Invalid Args, 602 Optional Action Not Implemented, the same in UDA 1.0); `s:MustUnderstand` with faultstring MustUnderstand and no detail (SOAP 1.1, §4.4: the detail is for the Body). No other code is defined; 5a3 and 5a4 add theirs with a cited source. Every reply carries an empty `EXT` header, written as UDA writes it, by a direct assignment to the header map (`Header.Set` canonicalizes it to `Ext`, as the DLNA listener's replies have it). A control request refused before its body is read asks for its connection to be closed, so net/http does not read the rest of the body to keep it (a description's 405 and a 404 do not: net/http reads at most 256 KiB of what is left to keep the connection, or closes it). `FuzzControlRequest` drives the handler with any SOAPAction, Content-Type and body and holds every answer to the table.

- **GENA is 501.** UDA 1.1 (§4.1.2) has a publisher that cannot accept a subscription answer a 5xx; 501 Not Implemented says it is not a passing condition, where 503 invites a retry, and 412 (Precondition Failed) would tell a well-formed request it was malformed. Never 200: a controller that held a SID would wait on events that never come. UNSUBSCRIBE is the same, with no subscription to cancel. Neither carries a SID or a TIMEOUT. Any other method at an eventSubURL is 405 with `Allow: SUBSCRIBE, UNSUBSCRIBE`. 1-bit subscribes to nothing; a controller that needs events (Kazoo, Linn's apps) finds the refusal at once. GENA itself is out of scope.

- **The tests.** `internal/player/lan/lantest` is the LAN the surface's tests and serve's run on: an address source the test sets, and listeners on 127.0.0.1 whose accepted connections report the LAN address the listener stands for and the source each `Dial` names (a listener's Accept waits for the dial to record it, since the kernel may complete the handshake before or after the dialler returns), so admission, the limits and the URLs are tested with real sockets and no LAN. Serve's boot tests hand the box through `serveOpts.playerOpenHome`; `hostLAN`, the interfaces the production address source lists, is a box with no interface in cmd/bridge's suite (its TestMain, beside `hostTrees`), so a serve test that turns the surface on without a box binds nothing of the host, which the "no box of the test's" case checks; its control gives `hostLAN` an interface with an address no host here holds, so the control binds nothing real either. The platform test binds loopback alone, restricted to the loopback interface, which `net.Interfaces` is read for and nothing else. The stop's phases are marked by seams (`Seams.Handling`, `Stopping`, `Forcing`), never by a sleep; the deadlines the limits tests wait on are real time, each test waiting a bound well inside the next deadline that could close the connection instead.
