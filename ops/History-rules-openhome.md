## The player's OpenHome surface (B470 PR 5a2a)

- **`output.player.openhome` is the opt-in, off by default, and it stays off by default until the owner decides it after B470 5b and 5c.** Why off: 1-bit finds a Source by SSDP and, for a host advertising one, never probes for MPD (the iOS research note on 7b66325d, MPDP:5-9, 151), so publishing a Source removes that host's MPD row, the one way to cast there today; before PR 5a3 a cast start aborted on its required source read (`SourceIndex`, 602 then) with the previous output kept, and from 5a3 to 5a4 it read the Source (`Standby`, `SourceXml`, `SourceIndex`) and `TracksMax` and stopped at its inserts (`Insert`, 602 until 5a4). PR 5a4 implements every write, so a cast to the Source runs; the default stays off until 1-bit lists the bridge's player beside the box's MPD (5b and 5c), and the owner's dogfood turns it on in the owner's bridge.yaml (the runbook is in the 5a4 entry of `ops/engineering-log.md`). It is read once, from the boot snapshot (`planServePlayer`, with the player's other gates): a change applies when serve next starts, as the player's own block does. The surface starts inside the player's supervisor after launching the engine (without an engine-readiness gate) (`bridgePlayer.start`, `startOpenHome`), so a player that does not start (any gate, the engine refusing its storage) starts none of it: no socket, no goroutine. With the opt-in on and the player simply off (`enabled: false`), `planServePlayer` returns `openhomeOff` and `startServePlayer` logs "player: the OpenHome surface does not start" once; a player refused for another reason already says why (Validate's line, or "player: not started"), and the surface adds nothing to it. The port: `openhomePort`, nil for `DefaultOpenHomePort` (7792: nothing in the repo named it, and it follows 7788 to 7791), 0 for a port the kernel picks per address (config-lifecycle.md's ports admit 0), every URL then carrying the port the request arrived on. It is validated as its neighbours are: the block's strict reader takes the two keys (a word, a list or a fraction leaves the block unread, naming the key and its line), and `Problem` refuses a number outside 0 to 65535, either turning the player off with a reason that quotes no value (config-lifecycle.md's rule on values; `TestNoLoadRefusalOrWarningCarriesAValue` covers the key through envBindings). Both keys take an environment override as every scalar of the block does (`BRIDGE_OUTPUT_PLAYER_OPENHOME`, `BRIDGE_OUTPUT_PLAYER_OPENHOME_PORT`, from `envBindings`'s walk; `TestThePlayerIsEnvSettableButItsSerialIsNot`), applied at Load, so they are the boot snapshot's too, and a value the variable does not read as is ignored with a warning naming the variable alone. A fraction read as its whole part until backlog B528 (2026-10-24), as on every whole-number line of the block, since yaml.v3 decodes a float into an int by dropping what follows the point: `openhomePort: 7792.9` bound 7792. The reader now refuses it, and any float yaml.v3 would change on the way in, as it refuses a word there (`playerReader.whole`, `exactInteger`), and takes a float whose value is a whole number the int holds (`7793.0` reads as 7793), so no value the file holds changes (`TestAWholeNumberOfThePlayerTakesNoFraction`; the rule for every whole-number setting is config-lifecycle.md's). With the surface on, `PlayerEnabled` refuses a port another listener of serve binds (`openHomePortClash`): `listenAddress`'s (the API, TCP and HTTP/3's UDP), `adminAddress`'s, `dlna.listenAddress`'s whether or not DLNA is on (it can be turned on and the surface would then lose the race for the port), and `output.loopbackPort`'s (bound once `output.mpd` resolves on, which can happen at any time after boot through `OnActive`); an empty address is its default (applyDefaults fills them, a Config built in memory may not); 0 clashes with nothing. It is a refusal of the player, as the block's other refusals are, and Validate logs it once each time the reason changes (`logPlayerOff`); it does not clash when the surface is off, since the port is then never bound. Rejected: refusing the surface alone, which would need a once-logger of its own and a second predicate beside `PlayerEnabled` for one value of the block; and refusing the clash whatever the opt-in, which would turn a player off over a port it never binds. A numeric `--addr` at serve time can move the API onto the port after Load: planning then refuses the player, before its surface binds. Serve compares that refusal with the pre-override plan, so a new reason is logged once instead of silently marked already reported. A reason unchanged from Load remains already reported: `servePlayerPlan.off` is a string, so equality compares the reasons' text, not the identity of the errors `PlayerEnabled` returned. A new API-port clash names `listenAddress, set by --addr`, without the address or port, so the warning identifies the source rather than only the file's setting. Since the iOS repo's B550 (2026-10-25), 1-bit 2.2 no longer counts a Source whose manufacturer is the bridge's as making its host an OpenHome host, so its MPD probe still runs and it lists both; 1-bit 2.1 and earlier still lose the box's MPD row while the Source is on the LAN, which the console's switch says. **B612 (2026-10-31, the owner's decision at the 0.2.2 release checks): the console's Player page has a switch that sets the opt-in** (`POST /api/output/player/openhome`, admin-console.md's Player page entry). The page set only `enabled` and the DAC, no console route could set the opt-in (the enabled route's decoder refused the key, and the settings PATCH takes no player key), so an operator who turned the player on from the page alone got a player the app could not reach. The default stays off: the switch changes what an operator can do, not what a bridge does unasked. The switch asks the port of the config it would save whatever `enabled` says (`config.OpenHomePortClash`, exported for it from `openHomePortClash`): `PlayerEnabled` asks it only of a player that is on with its surface on, and `Validate` only logs a player's refusal, so a clash saved with the player off would have turned the player off on the day it was turned on. A clash is 409 `player_refused` naming the setting, nothing written; an opt-in turned on with the player off is saved, and the surface starts once the player does. This is a refusal of the save, not of the player: `PlayerEnabled` still refuses the clash only for a player that is on with its surface on, the rejection above (refusing the clash whatever the opt-in) stands, and the enabled route turning the player on later refuses the same clash, as before. It takes no go-ahead (`interrupt`): serve reads the opt-in from its boot snapshot alone, and the running process reads the live one only through `PlayerEnabled`'s clash check (the hotplug watcher's settings, serve's player's withholding, the console's view), which a saved change leaves as it was or lifts. Measured through a real serve: a valid toggle while the player plays, and back while it is paused, leaves the engine playing and then paused, the DAC neither opened nor let go again, the surface the boot started listening where it listened, and no output report withholding before a barrier (`TestTheConsolesOpenHomeSwitchLeavesWhatPlaysAsItIs`); a negative control that skipped the clash check stopped playback at once, the output withheld `disabled` (`TestTheConsolesOpenHomeSwitchRefusesAClashAndChangesNothing`). The saved value is what the next start's plan reads (`TestTheNextStartReadsTheOpenHomeSwitchTheConsoleSaved`).

- **The surface is a listener of its own: one IPv4 socket per address `lan.Look` serves, never a wildcard and never on DLNA's listener, keyed by `lan.Address`, followed by a listing every 5 s.** DLNA's guards do not meet the player's rule: `servedOnlyListener` closes a connection whose local address is not served, and serves every LAN address to any source; `ownHostOnly` passes an empty Host, `localhost`, loopback literals, every advertised host and any address of this host, with any port. The player's rule is per connection (a source on the arrival address's link) and per request (the exact address and port), so it has a listener of its own, which DLNA's being off (its default) does not change. Each eligible IPv4 address of each eligible interface (`internal/player/lan`: up, running, multicast, not point-to-point, no Tailscale address, RFC 1918 or 169.254) gets its socket on the configured port; `lan.Look` lists the served addresses with their on-link prefixes and their interfaces' names and indexes, and every address the box holds, from one listing. The socket's key is the whole `lan.Address`: the brief asked for the address and its prefix, and the interface's index is in it too because the restriction (the next bullet but one) names the index, so a socket bound to an interface that was made again under another index would hear nothing. A listing every `Limits.Rescan` (5 s, and `Rescan` for a test or a later netlink trigger) updates the admission snapshot first, then withdraws discovery for each removed socket before closing each socket whose key is no longer listed (and the connections its server holds), then binds each new one; a listing that fails keeps what is bound and is said once a streak, since one failed listing must not take the surface off the LAN (servedAddrs keeps its snapshot for the same reason). A bind that fails (the port taken, the address gone between the listing and the bind) fails that address alone: it is in `Status.Failed`, said once until it binds or its error changes, and tried at the next listing; the player, the library and the rest of serve never see it. The surface closes a retired socket's listener itself as well as by its server's `Close`: `http.Server.Close` closes only the listeners `Serve` has begun to track, so a socket retired before its `Serve` goroutine first ran stayed open until that goroutine ran and found the server closed (found by `TestTheSurfaceBindsEachServedAddressAndFollowsThem`, one run in a few; no seam reaches that window, so no control). A retired socket leaves `Status` only once its connections are closed too (backlog B557, 2026-10-28). The listing dropped it from `Status` first (`s.sockets = kept`) and closed it after, and `http.Server.Close` closes the connections only once the socket's `Serve` has returned, so a run of that test in CI (on #1353) saw the address gone, sent a request on the kept-alive connection it held there and was answered 200 by the surface's own server: the request went on an established connection, which no other process can answer. Now `retire` marks the socket retiring, closes its listener, waits for its `Serve` goroutine to have done with its end (`served`; `Close` waits for `Serve` to return in any case), then closes its connections, and the listing drops it from `Status` after. A retiring socket's `Serve` goroutine no longer marks it `ended`, which `Status` reads as gone, since that goroutine returns before the connections are closed; `ended` still marks a `Serve` that returned on its own, which discovery's recheck of the live listeners needs (5a2b, round 2), and one that returned in the stop. `Seams.Retiring` holds each retirement between the listener's close and the connections', the state CI's run was in (the listener closed, the connection answered), and the test holds its three retirements there and requires `Status` to list the address, and at the first the kept-alive connection on it to be answered there and refused once `Status` drops the address; the wait for the `Serve` goroutine is what makes that state the same on every run. Rejected: checking that a 200 carries the surface's own instance token, the remedy for an answer from another process on a freed port, since nothing was dialled; and `Status` ignoring `ended`, which would let discovery republish a dead listener. Residual: a `Serve` that ends on its own leaves `Status` while its connections are open, until the listing it pokes retires the socket. A container on a Docker bridge is on a link the box serves when that bridge is eligible, as DLNA's residual says.

- **Admission is at accept, before any cap counts.** `admitting.Accept` asks the gate of each connection, in order: its local address is its socket's, while the listing serves that address (`destination_not_served`, which is also what a connection taken in the moment between a listing that dropped the address and the socket's close gets); its source is IPv4 (`source_not_ipv4`), not loopback (`source_loopback`), none of the box's own addresses (`source_own_address`: every interface's, eligible or not, from the same listing, since a connection from one of them is the box's own or a forgery), inside the on-link prefix of the address it arrived on (`source_outside_prefix`: not another address's, a secondary's included, nor another interface's), and of the LAN's classes (`source_not_lan`, `lan.IsLANAddress`: RFC 1918 and 169.254, so a mask a box was given by mistake, wider than its address's class, admits no public address; `TestAdmissionRefusesAtAcceptAndCountsNothing` serves 192.168.9.1/8 and refuses 192.169.0.5). Then the caps. A refused connection is closed at once with a linger of 0, so the peer gets a reset, unread and unanswered, and counts against no cap: a flood of refused connections cannot take an approved source's place. A refusal is logged once per kind and source, 32 at most, since a peer chooses its source. Then, at the request, row 1's second half: the Host must be exactly the address and port the request arrived on (`netip.AddrPort.String`), no default port elided, no name, no mapped or zero-padded spelling, no empty Host, or it is 400, before routing (a foreign Host on a path that is no route is 400, not 404). `http.Server.DisableGeneralOptionsHandler` is true, so Go does not answer `OPTIONS *` before this handler: `TestOptionsStarPassesThroughTheSurface` sends it through a real listener, with own and foreign Hosts, while running and in the stop window. A foreign Host is still 400 before the stop check; an own Host is 404 for the unknown route while running and 503 while stopping, all with EXT. That is DNS rebinding's answer: a page re-pointing its own name at the box sends that name. Rejected: admitting a source by any served address's prefix (a secondary address's link reaching the primary's socket), and a source check inside a handler, which would have counted the connection and read its request first.

- **The arrival interface is restricted where an unprivileged option exists.** IPv4 on Linux is the weak host model: an address bound on one interface takes a packet that arrives on another. A TCP handshake from outside the prefix needs a route back to its source, so a source in the prefix and a served destination refuse what they must in the ordinary case; the restriction is defence beside them. Linux: `SO_BINDTOIFINDEX`, set in the `ListenConfig`'s Control before the bind; an unprivileged process may set it, or `SO_BINDTODEVICE`, on a socket not bound to a device yet since Linux 5.7 (c427bfec18f2, "net: core: enable SO_BINDTODEVICE for non-root users"; before, both need CAP_NET_RAW), and a listening socket bound to a device is handed only a SYN that arrived on it (socket(7): "only packets received from that particular interface are processed by the socket"). Where the kernel refuses, the socket listens unrestricted and its restriction reads "none: the kernel refused SO_BINDTOIFINDEX (…)", never a failed bind: the prefix check holds either way. Not measured from this session: no Linux host was reached. macOS: `IP_BOUND_IF`, which an unprivileged process may set; measured on the dev Mac (darwin 27, 2026-10-23) with a throwaway probe: a loopback listener bound to en0, dialled on loopback, timed out (its SYN-ACK went out en0), and a listener on en0's address bound to en0 took this host's own connection, which arrives on lo0; so it scopes what the socket sends, and does not refuse a segment by the interface it arrived on (XNU's `inp_restricted_recv` filters by the bound interface only on interfaces marked restricted-receive). Elsewhere (Windows): nothing; `IP_UNICAST_IF` scopes sends, and the player runs on Linux alone. An index of 0 is left unrestricted and says so, since 0 means "no device" to these options. The residual: a router on the LAN that rewrites sources into the prefix (SNAT) is admitted, and so is anything on the link that holds an address in the prefix.

- **The limits.** `DefaultLimits`: 32 connections open and 8 from one source, counted once a connection is admitted (URLSession's default per host is 4 on iOS and 6 on macOS, by Apple's documentation, and 1-bit polls about once a second); 8 slots; a header read deadline (`ReadHeaderTimeout`, 5 s); the whole request's (`ReadTimeout`, 10 s); a control body's own, 5 s, set with `ResponseController.SetReadDeadline` once rows 2 to 5 have passed, so a body that trickles meets it where the whole request's would wait twice as long (`TestATrickledBodyMeetsItsDeadlineHoldingNoSlot` waits 5 s for the 408); a write deadline (`WriteTimeout`, 10 s from when the request's headers were read, which net/http sets per request, so a client that pipelines requests and reads none of the answers holds a write until it, and nothing else ends that write: no read deadline runs while a response is written, `TestAClientThatStopsReadingIsCutOffByTheWriteDeadline` with 4 KiB socket buffers); an idle deadline (`IdleTimeout`, 30 s; net/http takes `ReadTimeout` for an idle connection when none is set, which the test's 5 s wait tells apart); 16 KiB of headers read (`MaxHeaderBytes` 12 KiB and net/http's 4 KiB of bufio lookahead, as `dlnaMaxHeaderBytes` is derived), 431 past it; the body bound, 256 KiB (row 6). A slot is taken once a request's body is read, never before, so a client that trickles holds no slot, and past the slots a request is 503 at once, never queued. The descriptions take a slot too (they have no body). The server's `ErrorLog` is `handshakelog.ErrorLog()`, so net/http's own lines keep no client address (cli-serve.md's rule for serve's servers).

- **The stop.** `Surface.Stop`, once: `stopping` is set, so every request from then on is 503 with its connection closed (`Seams.Stopping` runs there); discovery is cancelled and withdrawn while HTTP remains bound (5a2b below); the listing loop is cancelled and joined within `Limits.Join` (abandoned and counted past it, and a socket it binds after the stop is closed at once); each listener is closed (`Shutdown` closes only what `Serve` tracks), then each server shut down at once within `Limits.ShutdownGrace` (2 s), which closes idle connections and waits for the requests under way; only a Shutdown result matching `context.DeadlineExceeded` or `context.Canceled` marks a server late (an already-closed listener can return `net.ErrClosed` even after a clean drain); a server whose grace ran out has its connections closed (`Seams.Forcing` runs first); then the Serve goroutines and the handlers are joined within `Limits.Join` (1 s), one deadline for both, what is still running counted in `StopReport.Abandoned` and said. A handler held past its connection's close (a test's seam; production's return at once) is the one thing that can outlive the stop, and the report says so. The join covers the Serve goroutines and the handlers, not net/http's goroutine per connection, so a request that goroutine read just before the stop closed its connection can still reach the handler after the join: it is refused 503 like every request after the stop, with the EXT header every reply carries, onto a connection already closed (`TestARequestAfterTheStopsJoinIsRefusedLikeEveryReply`; red first, it had no EXT header, written only after the handler's count was entered). `StopBound` is the sum, 4 s with the defaults, which serve's player adds to its stop's outer bound. Serve's player stops the surface first in its shutdown (`bridgePlayer.shutdown`, `stopOpenHome`), then the engine, then the backend, so no request reaches the engine as it stops; `TestServeRunsTheOpenHomeSurfaceOnlyWithItsOptInAndThePlayer` observes the engine's Run still live directly at `Seams.Stopping`. Its negative control moves `stopOpenHome` after the engine and backend joins but before the final journal line; a journal-order comparison alone could not detect that. `TestIdleSocketsNeverMakeACleanStopForced` repeatedly stops two sockets with completed requests and requires neither a forced report nor a forcing hook.

- **A panic in the surface's listing stays in the surface.** The listing loop is the surface's one goroutine of its own beside net/http's, which recovers a handler's panic per request; a panic in the address source (production's is `lan.Look` over the host's interfaces, a test's anything) or in the listing would otherwise end the process, the library with it, which "faults stay in the player" (player.md's 4b3 bullet) forbids. The loop's deferred recover logs at Error with the stack, and with the value only when it is a `runtime.Error`, as `logPlayerPanic` does (a value code panics with could quote what the listing read: the test panics with a path and checks the line for it), publishes so a watcher of `Changed` wakes, and returns: the surface withdraws discovery, serves the addresses it has bound, follows the interfaces no more until serve next starts, and stops as before (the loop's done channel is closed by the defer registered before the recover's, which runs after it, so Stop's join sees the loop gone once the line is written). Red first: the panic crashed the test binary. The engine's own goroutines are the known limit 4b3 left (backlog B523).

- **Only `/openhome/` is served.** Routes are exact (no `ServeMux`, so no redirect for an unclean path): `description.xml`, and `scpd.xml`, `control` and `event` under `/openhome/<service>/` for the four services' paths (`product`, `playlist`, `info`, `time`); any other path is 404, the admin's, `/v1`'s, DLNA's and media's included, and no reply carries a CORS header. The descriptions answer GET and HEAD, 405 to anything else. The device description is built per request from the address and port the request arrived on (`arrivedOn`, `http.LocalAddrContextKey`), not from Host, so every URL in it is absolute and on the address a controller found, on any of the box's LANs and on a port the kernel picked. Its fields: deviceType `urn:av-openhome-org:device:Source:1`, UDN `uuid:` and the player's UUID (`config.EnsurePlayerUUID`, never the MediaServer's `deriveDLNAUDN`), manufacturer `1-bit`, manufacturerURL `https://1-bit.app`, modelName `1-bit Bridge Player` (which 1-bit never reads), modelNumber `version.ServerVersion`, modelDescription `The 1-bit bridge's own player`, no serialNumber (1-bit hides a DLNA twin by manufacturer and serial on the same host), and the four services, each with its type, its ID (`urn:av-openhome-org:serviceId:<name>`) and its three URLs. modelDescription and the vendor fields are neither of upmpdcli's strings (manufacturer "JF Light Industries", modelDescription "UPnP front-end to MPD"), which 1-bit does not offer, and the research note says "1-bit" matches none of the iOS renderer profiles; their own substrings (RPR:453-484) were not read from this session (an owner check). No Volume service: the player's output is fixed, and 1-bit draws no volume section without one.

- **The friendlyName.** `FriendlyName(room)`: invalid UTF-8 bytes dropped, then every rune outside XML 1.0's Char production (controls other than tab, newline and carriage return, U+FFFE, U+FFFF), then the first 64 runes kept, so a cut never splits a rune; a room that keeps nothing is `1-bit Bridge Player`; the description then escapes it (`xml.EscapeText`). It holds whatever reaches it: config's validation of `room` (UTF-8, no control character, 64 characters) is unchanged, and the builder does not trust it. A room equal to another renderer's name on the same host less "-UPnP/AV" would pair the Source with that renderer in 1-bit; that is the owner's to avoid, and nothing here can see the other renderer.

- **The four SCPDs are the bridge's own tables.** `services.go` holds each service's actions (each with its arguments in order, their directions and their related state variables) and state variables (each with its type, allowed values and eventing), written from OpenHome's action tables, and `service.scpd` generates the description. OpenHome's own files, ohNetGenerated at 22feef5262ed28432783c9bf16bdeb31d4c8bb18 (`OpenHome/Net/Service/Upnp/OpenHome/`, MIT), are test data with their `License.txt` and a README (`testdata/upstream`); no file of theirs is embedded or built in, so no third-party notice ships (the release has no notices mechanism, backlog B500). `TestOurSCPDsAreUpstreamsInventory` reads both as a controller reads an SCPD and compares them exactly, so a table that drifts from OpenHome's fails; `TestTheUpstreamFilesAreTheirPinnedBytes` holds the copies to their SHA-256s (two are CRLF, and `.gitattributes` keeps them unconverted). The SCPDs keep OpenHome's `sendEvents` though GENA is refused: they describe the service as OpenHome defines it.

- **The SOAP layer.** (B470 PR 5a3: a request that passes is its action's to answer, `actions.go`, the read actions' section: a write 602 until PR 5a4, a read from one engine snapshot; 501 and 605 are defined beside 401, 402 and 602, and the reads' OpenHome codes (Playlist's 800, Product's 801) beside them, each with its source. PR 5a4: every write is answered by its writer, `writes.go`, the write actions' section; 602 is no longer defined, since no action answers it, and 600 Argument Value Invalid is, beside 401, 402, 501 and 605, with OpenHome's 800 to 804 and 899 and Product's 801, each with ohPipeline's description. What follows is the 5a2a record, whose 602 for every request held until 5a3.) The table is `soap.go`'s and the rules file's, in its order: row 1, admission and the Host; row 2, POST (405 with `Allow: POST`); row 3, no `Origin` header at all, empty and `null` included (403), before the body is read, since no controller sends one and a browser always does; row 4, one `Content-Type`, `text/xml` with a charset of utf-8 in any case, quoted or not, or none (`mime.ParseMediaType`; 415); row 5, one `SOAPAction`, quoted or not, a single `#` between this URL's service type and one of its actions (fault 401, a missing one included); row 6, the body through `http.MaxBytesReader` at 256 KiB (413), read to EOF under its own deadline (408 at it, 400 for another read failure); then a slot (503 at once); row 7, the XML through `encoding/xml` in strict mode with no charset reader (so a declared encoding other than UTF-8 and bytes that are not UTF-8 are 400): no directive (DOCTYPE, ENTITY), the declaration first or not at all, other processing instructions ignored and at most 4, at most 128 elements and 8 deep, at most 64 KiB and 8 KiB per in-argument of decoded text (Insert's 88 KiB holds the engine's 64 KiB of metadata, escaped or not, beside its URI), and nothing after the envelope but white space (400 for each); row 9, the action's in-arguments in the SCPD's order, each with no namespace or the action's own (children of a default-namespace action inherit it), none missing, repeated, unknown or nested, each parsing as its state variable's type: `ui4` and `i4` decimal and in range (`strconv.ParseUint` and `ParseInt`: no sign on ui4, an optional one on i4), `boolean` 0, 1, true, false, yes or no in any case, `bin.base64` strictly (`base64.StdEncoding.Strict()`, which ignores line breaks, so they are refused first), `string` any text within row 7's bound; for every action, those with no argument included (fault 402). Nothing is trimmed. The serve test sends a valid Insert and requires the queue to stay empty; its positive control calls the engine with the same arguments, observes one entry, then deletes it. Play on an empty queue was unobservable and proved nothing. Every request that passed was fault 602 in 5a2a: no action was implemented, since no controller might read an ID or a token before the restored identity's policy (5a0), and nothing was read from the engine or done to it. That policy is in place since #1331 (e263ee86), before 5a3's reads: a backup carries the reservation, stamped with the identity, and a restore raises both marks past anything the snapshot's identity handed out (the read actions' first entry, the last section). Faults: HTTP 500, `text/xml; charset="utf-8"`, `s:Client`, `UPnPError`, the code and its description (UPnP Device Architecture 1.1, §3.2.2: 401 Invalid Action, 402 Invalid Args, 602 Optional Action Not Implemented, the same in UDA 1.0); `s:MustUnderstand` with faultstring MustUnderstand and no detail (SOAP 1.1, §4.4: the detail is for the Body). No other code is defined; 5a3 and 5a4 add theirs with a cited source. Every reply carries an empty `EXT` header, written as UDA writes it, by a direct assignment to the header map (`Header.Set` canonicalizes it to `Ext`, as the DLNA listener's replies have it). A control request refused before its body is read asks for its connection to be closed, so net/http does not read the rest of the body to keep it (a description's 405 and a 404 do not: net/http reads at most 256 KiB of what is left to keep the connection, or closes it). `FuzzControlRequest` drives the handler with any SOAPAction, Content-Type and body and holds every answer to the table.

- **GENA is 501.** UDA 1.1 (§4.1.2) has a publisher that cannot accept a subscription answer a 5xx; 501 Not Implemented says it is not a passing condition, where 503 invites a retry, and 412 (Precondition Failed) would tell a well-formed request it was malformed. Never 200: a controller that held a SID would wait on events that never come. UNSUBSCRIBE is the same, with no subscription to cancel. Neither carries a SID or a TIMEOUT. Any other method at an eventSubURL is 405 with `Allow: SUBSCRIBE, UNSUBSCRIBE`. 1-bit subscribes to nothing; a controller that needs events (Kazoo, Linn's apps) finds the refusal at once. ## Source discovery (B470 PR 5a2b)

The Source uses `Config.SSDP`, supplied by serve. Its single worker owns its
handle; the surface waits for transaction acknowledgements without holding
its locks across discovery I/O. `Ready` closes on the first bound listener
entering HTTP Serve, separately for each Surface instance. Neither Start
returning nor the player's ready channel proves this. Engine readiness gates
nothing: since B470 PR 5a3 a read answers 501 while no engine runs, and every
write remains 602 until 5a4. Seven ordered targets derive from
the description's services; UUID, SERVER and each actual bound port are
checked against the packets and descriptions. Repeats and byebye use the
same targets. DLNA's identity, token, selection and goldens stay untouched.

The immutable discovery view contains only bound listeners plus the last
good inventory's Own addresses. The Source hook performs the shared TCP
source rule without logging, counting connections or acquiring slots. It
requires the endpoint still be in that view. Own-only changes replace the
view even when the handle needs no Update. A failed listing keeps the last
good view. Removed endpoints leave admission before withdrawal; their HTTP
listeners stay bound until withdrawal completes. New listeners enter Serve
before Register/Update. A prefix or interface change therefore has two
phases, which also permits rebinding the same address. Unexpected HTTP Serve exit clears the immutable admission view and cancels
the current registration lifetime immediately, before queuing reconciliation;
intentional close keeps its existing path.

Empty is Withdraw and a cleared handle, never Update after Withdraw. Partial
and total SSDP failures inspect Active/Failed and retry on the next listing,
even without HTTP changes; failed HTTP binds also retry. Initial interface
life is zero, sharing DLNA's membership; aliases/prefix edits retain it.
An observed absent (index, name) advances its life for reappearance. Identical
removal/recreation between polls cannot be observed: the five-second listing
and Rescan hook are unchanged, and no new netlink source is invented.

`Refuse` freezes publication, cancels normal discovery work and sets HTTP's
503/connection-close state while leaving listeners bound. `Withdraw` joins
discovery alone; `StopContext` then performs the existing bounded HTTP stop.
The detached withdrawal deadline is at most five seconds, shortened by the
caller's deadline. A registration's context is its lifetime: canceling a
short operation context immediately after Register would silently stop
answers/repeats. Late bind/Register/Update completion is retired, never
published by a stopped surface. Loop panic withdraws discovery while leaving
the existing HTTP surface until Stop. Supervisor exit stops the surface before
the engine; no restart policy is added. The default four-second HTTP bound
stays HTTP's; serve adds the five-second discovery allowance separately.

Tests use `lantest.NewMemory` and the instance `SSDPNetwork` fake socket model.
The real HTTP server, SSDP dispatcher and engine run without host listeners,
multicast, audio tree reads or PCM opens. The engine retains its storage probe.
The pre-existing loopback suite remains the place for OS buffer/half-close
and platform restriction checks. Barriers park binds and byebyes, asserting
503 and a live engine while withdrawal is held. Negative controls and gate
results are recorded with the 5a2b engineering-log entry and review report.

Discovery does not prove casting or bit-exact output. 1-bit's required
SourceIndex read failed 602 then and kept the previous output (since B470
PR 5a3 it is answered, and a cast start stops at its inserts, 602 until
5a4); Source advertising suppresses MPD probing on that host. Keep the opt-in false. Owner
checks must measure Linux restrictions/capabilities and the actual 1-bit row,
MPD coexistence and restart removal. SNAT can still appear on-link, and
macOS IP_BOUND_IF scopes sends rather than arrival.

### Round 2: unexpected HTTP exit

An exit could leave a closed port advertising while the listing loop waited
for Register/Update. The discovery worker now owns a cancellable lifetime per
registration, separate from the surface lifetime. HTTP exit clears admission
and cancels that lifetime under the same lock used to publish the view; it
performs no SSDP I/O there. The next transaction withdraws the cancelled
handle, checks the queued listeners against the current bound set and creates
a fresh registration. This pauses the whole Source registration, including
survivors, until that transaction; MediaServer is unaffected. Normal retiring
and stop paths stay unchanged. A write already handed to the kernel cannot
be recalled.

`TestSourceHTTPExitCancelsPendingAdvertisement/Register` holds initial
registration at OnListen, before the cancellation check; `/Update` begins with an advertised
Source and holds an update adding another interface. Both close the HTTP
listeners and join their Serve goroutines before releasing SSDP, require no
subsequent alive for the dead listeners, then prove a later bind advertises
again. The initial Register regression failed before the fix; removing the
invalidation fails both subtests. These are in-memory network tests, not a
claim about real kernel packet queues.

### Round 3: HTTP invalidation joins writes already under way

Cancelling the lifetime alone did not join a normal send past its cancellation
check. Round 2's OnListen parks were before that check. The Source now supplies
one SSDPSendBarrier per registration lifetime. Unexpected HTTP exit clears the
view and cancels under the publication lock, then releases that lock and
invalidates the captured barrier. Alive and reply writes take its read lock
across the final lifetime check and write; invalidation takes its write lock.
It therefore either prevents a write or completes only after that write ends.
Each write already has the burst's one-second deadline; concurrent writes use
read locks so their bounds overlap. No surface/publication lock spans this
wait. Byebye bypasses the barrier and still uses its own withdrawal deadline.
The whole Source still pauses until reconciliation withdraws and re-registers
the bound remainder, now with a fresh barrier. MediaServer leaves it nil.

`TestSourceHTTPExitJoinsAnAliveAlreadyWriting` parks the initial alive inside
OnSenderWrite, after cancellation was checked and before a packet is recorded.
The hook honors the installed sender deadline. The test closes HTTP and joins
s.serving before releasing the hook, then checks that no alive with the dead
LOCATION was recorded after invalidation completed and that all seven byebyes
carry that LOCATION. Before the fix it recorded one late alive; with the fix
the write expires before the join returns. Restoring the check-before-write-only
path reproduces the same assertion failure. These are fake-network observations,
not a claim that a kernel-queued packet can be recalled. The existing Register
and Update parks still check cancellation before the write and later recovery.
